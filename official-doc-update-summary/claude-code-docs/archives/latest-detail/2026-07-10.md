## 1. auto mode がリサーチプレビューから正式機能へ

auto mode を「リサーチプレビュー（research preview）」と述べていた記述が、今回の差分で公式ドキュメント本文から一斉に消えました。権限モードページ（`docs/en/permission-modes`）の Warning は「auto mode はリサーチプレビューです。権限プロンプトを減らしますが安全性を保証しません」から、前段を落とした「auto mode は権限プロンプトを減らしますが安全性を保証しません」に変わりました。Desktop ページ（`docs/en/desktop`）では auto mode の利用可能条件の書き出しが「Auto mode is a research preview available to all users on the Anthropic API」から「Auto mode is available to all users on the Anthropic API」になりました。さらに権限設定ページ（`docs/en/permissions`）の権限モード表の `auto` 行、How Claude Code works ページ（`docs/en/how-claude-code-works`）の `Shift+Tab` で切り替わるモード一覧、用語集（`docs/en/glossary`）の「Auto mode」項からも、同様に「Currently a research preview」「Auto mode is a research preview.」の一文が削除されています。要件（Opus 4.6 以降または Sonnet 4.6 以降、Team / Enterprise では Owner による有効化）自体は変わっていません。

これに関連して、changelog の v2.1.207 では **Amazon Bedrock / Google Cloud's Agent Platform / Microsoft Foundry で auto mode が `CLAUDE_CODE_ENABLE_AUTO_MODE` の opt-in なしに利用できるようになった**こと、無効化は設定の `disableAutoMode` で行うことが述べられています。あわせて auto mode は `.claude/settings.local.json`（リポジトリに同居するローカル設定）から `autoMode` を読まなくなり、`~/.claude/settings.json` を使うよう変更されました。ただしこの 2 点はまだ changelog にしか現れておらず、権限モードページには `CLAUDE_CODE_ENABLE_AUTO_MODE` を設定するまで auto mode が `Shift+Tab` サイクルに出ないと述べる節が、また Desktop ページの管理設定表には `autoMode` が `.claude/settings.local.json` からも読まれると述べる記述が、いずれも旧内容のまま残っています。本文が追い付くまでは changelog の記述が新しい挙動を示すと考えるのが妥当です。

## 2. サードパーティプロバイダの既定モデルとエイリアス解決の更新

changelog v2.1.207 の「Changed Bedrock, Vertex, and Claude Platform on AWS to default to Claude Opus 4.8」に合わせて、各プロバイダのセットアップページとモデル設定ページが書き換えられました。Amazon Bedrock ページ（`docs/en/amazon-bedrock`）では、既定モデル表の Primary model が `us.anthropic.claude-sonnet-4-5-20250929-v1:0` から `us.anthropic.claude-opus-4-8` に変わり、「`ANTHROPIC_DEFAULT_OPUS_MODEL` がなければ `opus` エイリアスは Opus 4.6 に解決される」という説明も「これらの変数がなければ `opus` は Opus 4.8 に、`sonnet` は Sonnet 4.5 に解決される。各変数はエイリアスを特定バージョンに固定するために設定する」に改められました。Google Cloud's Agent Platform ページ（`docs/en/google-vertex-ai`）も同じ書き換えで、Primary model は `claude-sonnet-4-5@20250929` から `claude-opus-4-8` になっています。Claude Platform on AWS ページ（`docs/en/claude-platform-on-aws`）では `opus` の解決先が Opus 4.7 から Opus 4.8 になり、モデル固定の例も `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-4-8` に更新されました。

モデル設定ページ（`docs/en/model-config`）の「Model aliases」節では、従来 1 段落に押し込まれていたエイリアスの解決先が**プロバイダ別の箇条書き**に整理されました。Anthropic API は `opus` = Opus 4.8 / `sonnet` = Sonnet 5、Claude Platform on AWS は Opus 4.8 / Sonnet 4.6、Amazon Bedrock と Google Cloud's Agent Platform は Opus 4.8 / Sonnet 4.5、そして **Microsoft Foundry だけが Opus 4.6 / Sonnet 4.5 に据え置き**です。エイリアスが古いモデルに解決されるプロバイダでは、完全なモデル名を明示するか `ANTHROPIC_DEFAULT_OPUS_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` を設定すれば新しいモデルを使える、という補足が続きます。同ページの `default` モデル設定でもアカウント種別ごとの既定が更新され、Claude Platform on AWS が Opus 4.7 から Opus 4.8 に、「Amazon Bedrock / Agent Platform / Foundry は Sonnet 4.5」だった 1 行が「Amazon Bedrock と Agent Platform は Opus 4.8」「Microsoft Foundry は Sonnet 4.5」の 2 行に分割されました。Fable 5 の安全分類器によるフォールバック先も、プロバイダごとに Opus 4.8 / Opus 4.7 と書き分けていたものが単に Opus 4.8 に一本化されています。

## 3. v2.1.207 リリース

公式 changelog に v2.1.207（2026年07月11日）のエントリが追加されました。セキュリティ面で重いのは 2 件です。1 つ目は**プラグインのシェルインジェクション修正**で、プラグインの hook / monitor / MCP `headersHelper` において、シェル形式のコマンド中に書かれた `${user_config.*}` が拒否されるようになりました。hook は exec 形式（`args` 配列）を使うか `$CLAUDE_PLUGIN_OPTION_<KEY>` を参照し、monitor と `headersHelper` は値をスクリプト側（設定ファイルまたはサーバの `env` ブロック）で読む必要があります。2 つ目は、**非対話実行（`claude -p` や SDK）で受け取ったリモート管理設定が、セキュリティ同意ダイアログを一度も表示しないまま「同意済み」として恒久的に記録されてしまう**バグの修正です。あわせて、プラグインのオプション値（`pluginConfigs`）はプロジェクトレベルの `.claude/settings.json` から読まれなくなり、ユーザー設定・`--settings`・管理設定だけが尊重されるようになりました。

体感に効く修正としては、**長いリスト・表・段落・コードブロックを含む応答をストリーミングしている間にターミナルが固まり、キー入力が遅延する問題**が直りました。応答のストリーミングが終わったときにトランスクリプトが回答の先頭より上へ飛んでしまう問題、良性のシステム生成の会話更新が誤ってプロンプトインジェクション警告を出す問題、自動アップデータが毎リリースで `~/.local/bin/claude` のカスタムランチャースクリプトやシンボリックリンクを上書きしてしまう問題（`/doctor` が外部管理のランチャーを報告するようになりました）も修正されています。auto mode とモデル既定の変更については本サマリのハイライト 1・2 を参照してください。その他多数の不具合修正・改善が含まれます（「軽微な更新」を参照）。

> 本リリースの内容は changelog ページにのみ記載され、対応する通常ドキュメントページに個別の節が無いため、参考リンクは省略しています（changelog リンク不使用ポリシー）。

## 4. Agent SDK (Python) の SystemPromptFile

Agent SDK の Python リファレンス（`docs/en/agent-sdk/python`）に `SystemPromptFile` 型が新設されました。`ClaudeAgentOptions.system_prompt` の型が `str | SystemPromptPreset | None` から `str | SystemPromptPreset | SystemPromptFile | None` に広がり、`{"type": "file", "path": "..."}` を渡すことでシステムプロンプトをディスク上のファイルから読み込めます。型は `type: Literal["file"]` と `path: str` の 2 フィールドのみで、SDK はこれを CLI の `--system-prompt-file` フラグにマップします。

ファイル形式が必要になる理由も明記されました。文字列で `system_prompt` を渡すと、SDK はそれを CLI サブプロセスの argv に載せるため、**API リクエストを送る前に OS のコマンドライン長制限に当たります**。Linux では単一引数が約 128KB を超えるとプロセス生成時に `Argument list too long` で失敗し、Windows ではコマンドライン全体が約 32KB に制限されるため、文字列形式はより低い閾値で失敗します。大きなプロンプトを扱う場合はファイル形式を使う、という使い分けです。

- [Agent SDK reference - Python (SystemPromptFile) - Claude Code Docs (日本語)](https://code.claude.com/docs/ja/agent-sdk/python#systempromptfile)
- [Agent SDK reference - Python (SystemPromptFile) - Claude Code Docs (English)](https://code.claude.com/docs/en/agent-sdk/python#systempromptfile)

## 1. Claude Desktop on Linux にトラブルシュート節を新設

Claude Desktop on Linux（beta）ページ（`docs/en/desktop-linux`）に「Troubleshoot」節が新設され、その配下に「Unable to locate package claude-desktop」が置かれました。`sudo apt install claude-desktop` が `E: Unable to locate package claude-desktop` で失敗するのは apt が追加したリポジトリを見つけられていないケースで、確認すべきこととして 3 点が挙げられています。`cat /etc/apt/sources.list.d/claude-desktop.list` でリポジトリエントリの `deb` 行が書き込まれているか（空・不在ならリポジトリ追加ステップをやり直す）、`dpkg --print-architecture` が `amd64` か `arm64` を返すか（リポジトリはそれ以外のアーキテクチャ向けパッケージを公開していない）、`sudo apt update` を再実行して `downloads.claude.ai` 関連のエラーが出ていないか（ネットワークまたは鍵のエラーなら、リポジトリは追加されたが到達・検証できていない）です。これらが揃っていてもパッケージが見つからない場合は、ダウンロードした `.deb` からのインストールに切り替えるよう案内されます。

あわせてインストール手順の導入文に「ターミナルを開き、各ステップのコマンドを実行してください」の一文が加わりました。

- [Claude Desktop on Linux (beta) (Unable to locate package claude-desktop) - Claude Code Docs (日本語)](https://code.claude.com/docs/ja/desktop-linux#unable-to-locate-package-claude-desktop)
- [Claude Desktop on Linux (beta) (Unable to locate package claude-desktop) - Claude Code Docs (English)](https://code.claude.com/docs/en/desktop-linux#unable-to-locate-package-claude-desktop)

## 2. エラーリファレンスの見出しアンカー id の変更

同ページ冒頭のエラーメッセージ対応表の該当行、1M コンテキストのエラーや「Model is not a recognized model id」からの相互参照といったページ内リンクも新しい id に更新されています。ページをまたぐ参照も同様で、トラブルシューティングページ（`docs/en/troubleshooting`）の「`model not found` または `you may not have access to it`」の行と、モデル設定ページ（`docs/en/model-config`）のモデル名検証の説明が、いずれも `#theres-an-issue-with-the-selected-model` を指すようになりました。旧 id を指す外部リンクやブックマークは、この変更後は該当セクションに解決されません。

- [Error reference (There's an issue with the selected model) - Claude Code Docs (English)](https://code.claude.com/docs/en/errors#theres-an-issue-with-the-selected-model)

## 軽微な更新

<!-- light:minor-updates:start -->
今回の軽微な更新は、changelog に追加された v2.1.207 のうちハイライトで扱わなかった項目と、リファレンスページ側の小規模な字句・リンク修正です。ハイライト・大幅更新で扱った項目は再掲しません。単一リリース（v2.1.207）のみのため、各項目へのバージョン併記は省略します。

**機能改善**

- agent view で、同じテキストをもう一度貼り付けると、折り畳まれた `[Pasted text #N]` プレースホルダが 2 つ目を増やす代わりに展開されるようになった。
- agent view で、ブロック中セッションの peek が質問を先頭に置き、同じタイムスタンプを 2 度並べる代わりに `waiting 3m` のような言葉による経過時間を表示するようになった。
- プラグインのオプション値（`pluginConfigs`）がプロジェクトレベルの `.claude/settings.json` から読まれなくなり、ユーザー設定・`--settings`・管理設定のみが尊重されるようになった。

**バグ修正**

- 良性のシステム生成の会話更新が、誤ってプロンプトインジェクション警告を引き起こす問題を修正。
- `cd` を含む複合コマンドで、出力リダイレクト先が `/dev/null` だけの場合にも権限確認が出る問題を修正。
- 応答のストリーミングが終わったときに、トランスクリプトが回答の先頭より上へ飛んでしまう問題を修正。
- `worktree.sparsePaths` を使う最後の worktree を削除したあとも `extensions.worktreeConfig` がリポジトリの `.git/config` に残り、`tea` のような go-git ベースのツールが壊れる問題を修正。
- ルールの glob・skill のパス・`.ignore`・`.worktreeinclude` に不正な角括弧パターンがあると、ファイル読み取り・ファイル候補表示・worktree 作成が壊れる問題を修正。
- エージェントチームで、不正な形式のチームメイト mailbox メッセージがあると、mailbox ファイルを手で消すまで毎秒エラーを繰り返すクラッシュループに陥る問題を修正。
- プラン承認によって自動命名されたバックグラウンドセッションが、その名前を agent view の行に表示しない問題を修正。
- git worktree に入ったバックグラウンドセッションが、エージェント一覧からコールドで開き直すと空で再開する問題を修正。
- Remote Control のタスク状態更新が、ネットワーク中断や認証情報の更新から接続が回復したときに失われる問題を修正。
- デスクトップアプリがホストする Remote Control セッションが、モバイルと Web でバックグラウンドエージェントとワークフローの進捗を表示しない問題を修正。
- Deep research の実行で、Fetch フェーズのエージェントが全て「unknown」とラベル付けされる問題を修正（チップにソースのホスト名が出るようになった）。
- Amazon Bedrock が API リクエストのたびに IAM Identity Center へ新しい AWS SSO 認証情報を要求し直す問題を修正。
- Windows で AWS の認証情報解決が停止（`credential_process` の固まりなど）したときに無期限にハングする問題を修正（60 秒のストール検知が働くようになった）。
- `/usage-credits` の金額入力が、貼り付けたタイムスタンプのような不正な値を黙って数字だけに切り詰める問題を修正。不正な金額はエラーで拒否され、1,000 ドルを超える金額は入力による確認を要するようになった。

## 2026年06月29日～07月03日(Week 27)

v2.1.195 から v2.1.201 までを対象に、5 つの機能を取り上げた週刊ダイジェストです。目玉は **Claude Sonnet 5** で、Pro・Team Standard・Enterprise サブスクリプションシートの新しい既定モデルになりました。Sonnet の価格帯でトップクラスのコーディングとツール利用を提供し、ネイティブの 100 万トークンコンテキストウィンドウと既定オンの適応的思考を備えます。API 価格は 2026年08月31日まで 100万トークンあたり入力 2 ドル / 出力 10 ドルのプロモーション価格で、利用には v2.1.197 以降が必要です。**Claude in Chrome** は直接 Anthropic プランを使う全ユーザー向けにプレビューを終えて一般提供になりました。**サブエージェントは既定でバックグラウンド実行**となり、Claude はサブエージェントの実行中も作業を続けて結果が出たら拾い上げます（結果が先に必要なときはフォアグラウンドで動かし、バックグラウンドのサブエージェントも権限確認は全てメインセッションに出ます）。**Claude Desktop on Linux** は Ubuntu 22.04 以降・Debian 12 以降、x86_64 と arm64 でベータ提供、**`/radio`** は Claude FM の lo-fi ラジオをブラウザで開きます（ブラウザが無い環境ではストリーム URL を表示。Amazon Bedrock / Google Cloud's Agent Platform / Microsoft Foundry では利用不可）。

「Other wins」として、Artifacts の一般提供と Pro・Max プランへの同梱、組織コンソールで設定できる**組織既定モデル**（自分でモデルを選んでいないとき `/model` に「Org default」と表示される）、`/skill-a /skill-b do XYZ` のような**スキルの多重起動で先頭の最大 5 つが全てロードされる**ようになったこと、`AskUserQuestion` ダイアログが既定で自動継続しなくなり `/config` でアイドルタイムアウトを opt-in する形になったこと、"default" 権限モードの **Manual への改称**、チャートとダッシュボードの設計指針を与える **`/dataviz` スキル**（実行可能なカラーパレット検証つき）、組み込みの Explore エージェントが Haiku ではなく**メインセッションのモデルを継承する**ようになったこと（Opus が上限）、`claude agents` から起動したバックグラウンドエージェントが worktree でのコード作業を終えたときに確認を求めず **commit・push してドラフト PR を開く**ようになったこと、`code-reviewer` のようなハイフン入り識別子の hook マッチャが部分一致ではなく**完全一致**になったこと（ハイフン入り MCP サーバの全ツールに一致させるには `mcp__brave-search__.*` を使う）、使用上限とは無関係な一時的なサーバレート制限エラーがサブスクライバ向けに**バックオフつきで自動リトライ**されるようになったこと、応答ストリームが 5 分間イベントを出さないと中断・再試行する**ストリーミングのアイドル監視が全プロバイダで既定オン**になったこと（`CLAUDE_ENABLE_STREAM_WATCHDOG=0` で無効化）が挙げられています。

## 2026年07月06日～10日(Week 28)

v2.1.202 から v2.1.206 までを対象に、2 つの機能を取り上げた週刊ダイジェストです。**Desktop の組み込みブラウザ**では、Claude がドキュメント・デザイン・その他任意のサイトを開き、ローカル開発サーバのプレビューと同じようにページを読み・クリックし・操作できます。ダイジェストはこのブラウザを「サンドボックス化され設定可能」と述べ、**閲覧セッションを永続化するかどうかを利用者が選べる**こと、外部サイト上のアクションは安全分類器が審査することを挙げています（閲覧セッションの永続性に関する記述は、Desktop リファレンスページ本文には無いダイジェスト独自の情報です）。もう 1 つの **`/doctor`** は、読み取り専用のレポートを出すだけでなく問題を診断して修正まで行える「セットアップ点検」になりました。インストールの健全性を検査し、未使用の skill / MCP サーバ / プラグインをそのコンテキストコストと突き合わせ、ローカルの `CLAUDE.md` を checked-in のものと重複排除し、codebase から導出できる `CLAUDE.md` の内容の削減を提案し、遅い hook を指摘します。まず検出結果を報告し、変更前に確認を求めます。エイリアスは `/checkup` です。

「Other wins」には、auto mode がセッショントランスクリプトファイルの改竄をブロックし、コンテキストから解決できない変数に対する `rm -rf` の前に確認するようになったこと、`/cd` の入力中のディレクトリパス候補表示、`/commit-push-pr` が `origin` に加えてリポジトリの設定済み push リモートへの `git push` も自動許可すること、ゲートウェイ利用者向けに `/login` が Anthropic 運営のパブリックゲートウェイエンドポイントに対応したこと、`EnterWorktree` がプロジェクトの `.claude/worktrees/` 外の worktree へ入る前に確認すること、バックグラウンドエージェントが Claude Code 更新直後にバックグラウンドで新バージョンへ上がること、agent view の行が生のツール呼び出しテキストではなく色付きの状態語と分類器が書いた見出しを表示し、既存 PR を編集・マージ・コメント・push したセッションが `claude agents` でその PR にリンクされることが並びます。加えて、**自動更新のバイナリダウンロードがメモリへのバッファリングからディスクへのストリーミングに変わり、アップデータのピークメモリ使用量が約 400MB 削減された**こと、**バックグラウンドタスクの通知が「人間の入力は発生していない」と明示するようになり、トランスクリプト内に捏造された承認が実行に移されるのを防ぐ**ようになったことが挙げられています（この 2 点は前回までのサマリで扱っていない、ダイジェスト側で明示された内容です）。`/code-review` の Opus 4.8 全 effort レベルでの指摘品質改善も再掲されています。

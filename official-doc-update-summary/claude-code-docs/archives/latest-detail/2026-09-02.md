## 1. PR ステータスバッジが gh CLI 必須ではなくなった

インタラクティブモードの **`PR review status`** 節の Note が書き換わりました。従来は「**GitHub リポジトリの PR ステータスには `gh` CLI がインストールされ `gh auth login` で認証されていることが必要**」の 1 文でしたが、今回は「**GitHub リポジトリの PR ステータスには GitHub トークンが必要で、Claude Code はリモートのホストに応じてトークンを探す**」に改められ、ホスト別の探索先が 3 項目で列挙されました。**github.com** では `GH_TOKEN` または `GITHUB_TOKEN`、あるいは `gh auth login` が保存したトークンを使い、どれも無い場合はフッターに `install gh for PR status`（`gh` CLI が未インストールのとき）または `gh auth login for PR status`（インストール済みのとき）と表示されます。**`GH_HOST` に設定した GitHub Enterprise ホスト**では `GH_ENTERPRISE_TOKEN` または `GITHUB_ENTERPRISE_TOKEN`、あるいは `gh auth login --hostname <host>` が保存したトークンを使い、同じヒントが出ます。**それ以外の GitHub ホスト**では `gh auth login --hostname <host>` が保存したトークンのみが対象で、無い場合はバッジもヒントも表示されません。環境変数によるトークン指定が明示されたことで、`gh` CLI を入れずに CI 用トークンだけでバッジを出せることが読み取れるようになりました。

**更新スケジュールの記述はページから削除されました**。従来は「更新頻度はプロバイダーによる」として、Anthropic API かつフィーチャーフラグ取得が有効なら「セッションで操作中は約 90 秒ごと、アイドル中・ターミナル非フォーカス中・ブランチに PR が見つからない状態が続く間はより低頻度」、Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry・Claude Platform on AWS またはフィーチャーフラグ取得が無効なら「60 秒ごと」と 2 通りが書かれ、さらに「入力が 1 時間無いと更新を止め、次のプロンプトで再開する」という段落が続いていました。今回はこれらが丸ごと消え、**`git push` または PR を変更する `gh pr` コマンド（`gh pr create` や `gh pr merge` など）がセッション内で成功した時点で更新される**という 1 文だけが残っています。ドキュメントから定期ポーリングの記述が消えた形で、実行時の挙動そのものがどう変わったかは changelog にも記載がないため、本サマリでは断定しません。GitLab のマージリクエストバッジ側でも「GitHub バッジと同じスケジュールで確認する」が外れ、「`glab mr create` または `git push` が成功した時点で更新される」だけになりました。

もう 1 つの追加が、**`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` を設定すると Claude Code は PR・MR のステータスを確認しない**という 1 文です。環境変数ページ側でも、この変数が止める通信の列挙に「[PR と MR のステータスバッジ](https://code.claude.com/docs/en/interactive-mode#pr-review-status)のチェック」が加わりました。一方、フィーチャーフラグ取得を切ったときにできなくなることの一覧からは「**アイドル中に PR レビューステータスバッジの更新頻度を落とすこと（代わりに 60 秒ごとに更新される）**」という項目が削除されています。設定リファレンスの `prUrlTemplate` でも、置換元が「**`gh` が報告した PR URL**」から単に「**PR URL**」になり、既定値の説明も「未設定。よってリンクは `gh` が報告した URL を使う」から「未設定」に短縮されました。いずれも PR URL の取得が `gh` CLI に固定されていないことと整合します。

## 2. サブエージェントを 1 つのモデルに固定する手順が独立セクションになった

サブエージェントのページに **`Run every subagent on one model`** という見出しが新設されました（`Choose a model` 配下の h4）。ページ見出しマップにも同じ 1 行が追加されています。前回サマリのハイライト 3 で扱った `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` は、これまで `Choose a model` 節の末尾に置かれた 1 段落で説明されていましたが、その段落は削除され、内容が拡充されたうえでこの新しい節へ移りました。

新しい節の骨子は、**`CLAUDE_CODE_SUBAGENT_MODEL` はあくまで既定値であり、サブエージェントの定義や Claude が渡すモデルの方が優先される**という前提の確認から始まります。そのうえで、すべてのサブエージェント・チームメイト・ワークフローエージェントに 1 つのモデルを適用するには `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` を `1` にも設定せよ（Claude Code v2.1.257 以降が必要）とし、**2 変数の組み合わせごとの結果**が 2 項目で示されました。**両方を設定した場合はサブエージェントが `CLAUDE_CODE_SUBAGENT_MODEL` のモデルで動き**、**`CLAUDE_CODE_SUBAGENT_MODEL_FORCE` だけを設定した場合はメイン会話のモデルで動きます**。従来の 1 段落にも同趣旨は書かれていましたが、条件分岐として並べ直されました。

実務向けの記述が 2 つ新たに加わっています。1 つは**設定例**で、すべてのサブエージェントを Haiku で動かすには設定ファイルの `env` ブロックに `"CLAUDE_CODE_SUBAGENT_MODEL": "haiku"` と `"CLAUDE_CODE_SUBAGENT_MODEL_FORCE": "1"` を並べて書く、という JSON が示されました。もう 1 つは**確認手順**で、サブエージェントが動いている間に `/tasks` を実行すると、そのサブエージェントの行に実際に動いているモデルが表示されるため、設定が効いたかを確かめられる、とされています。加えて、この変数が有効な間は **Claude Code がすべてのサブエージェント定義の `model` フィールドを無視し（組み込みの Explore と Plan を含む）、Claude はサブエージェント起動時にモデルを渡せなくなる**ことが明記されました。例外はこれまでどおり 2 種類で、`/fork` によるフォークと、`model: inherit` を持つスキルをサブエージェントで動かす場合はメイン会話のモデルで動きます。`CLAUDE_CODE_SUBAGENT_MODEL_FORCE` だけを設定した場合に組み込み Explore のモデル上限が残る点も、独立した 1 文として置かれました。

節の新設に伴い、**この機能を指すリンクのアンカーが `#choose-a-model` から `#run-every-subagent-on-one-model` へ張り替えられました**。対象は、エージェントチームのページの「チームメイトにも適用される」の 1 文、環境変数ページの `CLAUDE_CODE_SUBAGENT_MODEL` と `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` の 2 行、モデル設定ページの環境変数表の `CLAUDE_CODE_SUBAGENT_MODEL` の行です。組み込みサブエージェントの説明も書き直され、Explore と Plan の「メイン会話から継承する」に付く但し書きが「**`CLAUDE_CODE_SUBAGENT_MODEL` を設定したうえで全サブエージェントに強制した場合を除く**」という 2 段階の言い回しになり、`general-purpose` の行には解決順への参照に加えて「**この節が変数で各ソースを上書きする方法を示す**」という誘導が入りました。`Choose a model` 節の側にも「`CLAUDE_CODE_SUBAGENT_MODEL` を設定しただけでは組み込みの Explore と Plan が動くモデルは変わらない」に続けて「**変えるにはこの節を参照せよ**」の 1 文が加わっています。

## 3. 画像が溜まるとプロンプトキャッシュが壊れることが明文化された

プロンプトキャッシュのページの **`Actions that invalidate the cache`（キャッシュを無効にするアクション）** の一覧に、**`Accumulating many images`** が加わりました。これで一覧は 8 項目から 9 項目になり、`Compacting the conversation` と `Upgrading Claude Code` の間に挿入されています。

新しい節の内容は次のとおりです。まず前提として、**API は 1 リクエストが運べる画像と PDF の枚数に上限を設けており**、現在の数値は API ドキュメントの [Request limits](https://platform.claude.com/docs/en/build-with-claude/vision#request-limits) を見よ、とされています。さらに **Claude Code 側もリクエスト内の画像と PDF の合計サイズに上限を掛ける**ため、**大きなスクリーンショットは小さいものより少ない枚数で上限に達します**。そのうえで、次のリクエストがどちらかの上限を超えそうになると、**Claude Code は送信内容から古い画像と PDF をまとめて 1 バッチ分削除します**。1 枚ずつではなくバッチで削除するのは、次に削除が必要になるまでの余地を確保するためです。**削除された画像は Claude から見えなくなる**ため、再び必要になった場合は共有し直す必要があります。

キャッシュへの影響も説明されました。画像を削除するとその画像を含んでいたメッセージ自体が変わるため、**次のリクエストは該当する最も古いメッセージ以降を再処理します**。ただしバッチ単位で削除するので、**新しいスクリーンショットを追加するたびに遅くなるのではなく、バッチごとに遅いターンが 1 回発生する**形になる、とまとめられています。

同じページの **`Subagents and the cache`** 節も書き直されました。従来は「フォークは親のシステムプロンプト・ツール・会話履歴をそのまま継承するため最初のリクエストが親のキャッシュを読む」という文に、コンパクション要約とワークフローのファンアウトの話が続けて詰め込まれていましたが、今回は**「先行するリクエストがキャッシュしたプリフィックスを読める経路」として 3 項目の箇条書きに整理**されました。**セッションのコピー**は、`/fork` でコピーしたセッションが**隔離の指示をコピー元会話の末尾のメッセージとして受け取る**ため、元の会話が築いたキャッシュがそのまま残る、という説明が新規に加わったものです（前回サマリの軽微更新で触れた「`/fork` が新しいバックグラウンドセッションでプロンプトキャッシュを維持する」修正に対応します）。**コンパクション**は要約呼び出しが同じプリフィックス共有方式を使うという既存の説明、**ワークフローのファンアウト**は同一プリフィックスのエージェント群について最初の 1 つ以外を保留する話ですが、こちらは従来の「短時間保留する」から「**既定で最大 5 秒間保留する**」と具体的な時間が入りました。

- [Claude Code がプロンプトキャッシングを使用する方法 - Claude Code Docs (English)](https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache)

## 4. claude plugin validate がプラグインリファレンスに掲載された

プラグインリファレンスの CLI コマンド一覧に **`plugin validate`** の節が新設されました（`plugin details` と `plugin tag` の間）。34 行すべてが追加で、今回 `llms-full.txt` の中では changelog とサブエージェントに次ぐ分量です。ページ見出しマップにも同じ 1 行が加わりました。**コマンド自体は以前から存在し**、プラグインマーケットプレイスのページには検証の手順やチェック内容が既に詳しく書かれていて、changelog にも過去のリリースで多数の改善エントリがあります。今回新しいのは、他の `plugin *` サブコマンドと同じ体裁の**リファレンス項目が用意された**ことと、v2.1.259 で加わった `--json` が載ったことです。

節の内容は、公開前にプラグインまたはマーケットプレイスの構文とスキーマのエラーを確認するコマンド、という位置づけの説明から始まります。**終了コードは 3 通り**で、検証に通れば `0`、失敗すれば `1`、**渡したパスが読めない場合など検証の実行自体が失敗したときは `2`** です。引数 `<path>` はプラグインディレクトリまたはマーケットプレイスディレクトリを取り、プラグインを対象にした実行がどのファイルを見るかはマーケットプレイスページの [Validate a plugin or a directory without a manifest](https://code.claude.com/docs/en/plugin-marketplaces#validate-a-plugin-or-a-directory-without-a-manifest) を参照、とされています。オプションは 3 つで、**`--strict`** は警告をエラーとして扱い終了コード `1` を返すもので、認識されないフィールドのように実行時には許容される問題を CI で捕まえる用途が挙げられています。**`--json`** は検証レポートを 1 つの JSON オブジェクトとして出力するもので、終了コードは同じです（Claude Code v2.1.259 以降が必要）。残る 1 つは `-h, --help` です。

`--json` を付けたときに標準出力へ書かれる JSON のトップレベルフィールドも列挙されました。**`success`**（終了コードと同じ判定）、**`strict`**（警告をエラーとして扱ったかどうか）、**`target`**（解決済みの検証対象パス）、**`manifest`**（マニフェスト自体の検証結果。マニフェストの無い実行では `null`）、**`contents`**（ファイルごとの結果。各要素が `file` を持ち、`errors` / `warnings` / `notes` の配列を伴う）の 5 つです。**終了コード `2` の場合は標準出力には何も書かれず、エラーメッセージは標準エラーへ出ます**。最後に、対話セッション内では `/plugin validate <path>` が同じチェックをインラインで実行することが添えられています。

- [プラグインリファレンス - Claude Code Docs (English)](https://code.claude.com/docs/en/plugins-reference#plugin-validate)

## 5. managedMcpServers の新設と allowedMcpServers の適用範囲の変更

v2.1.259 の changelog に、MCP サーバーの組織配布に関する 2 件のエントリが入りました。**いずれも本サマリの作成時点では対応する通常ドキュメントページが更新されておらず**（設定リファレンス・MCP・管理設定のいずれにも記載が入っていません）、情報源は changelog だけです。そのため本節には参考リンクを付けていません。

1 件目は **`managedMcpServers` 管理設定の新設**です。changelog の記述は「**組織がすべてのユーザーに HTTP/SSE の MCP サーバーを提供できる（エントリの形式は `.mcp.json` と同じ）。実行するコマンドを指定したエントリはスキップされる**」というものです。stdio サーバーを配れないという制限は、既存のドキュメントにある LLM ゲートウェイ経由の配布の説明（ポリシーの `cli` ブロック内の `mcpServers` はブート時に拒否され、Claude Code クライアントへグループごとに MCP サーバーを配ることはできないため、ファイルベースの `managed-mcp.json` を各デバイスに置くか、開発者にローカルで追加させる）と方向性が一致します。なお既存ドキュメントにも `managedMcpServers` という名前は登場しますが、そちらは**ポリシーの `desktop` ブロック経由で Claude Desktop クライアントへ配る Claude Desktop 側の設定**を指しており、今回加わった Claude Code の管理設定とは別物です。同名のキーが 2 つの製品にあることになるため、ドキュメントの追従を待つのが安全です。

2 件目は **`allowedMcpServers` の適用範囲の変更**で、changelog では Changed（変更）に分類されています。記述は「**`allowedMcpServers` が、ユーザーが追加するサーバーのみを対象とするようになった。許可リストがこれまで除外していた `managed-mcp.json` に直接書かれたサーバーは、アップグレードすると読み込まれるようになる。読み込ませたくない場合は `deniedMcpServers` を使え**」です。設定を書き換えなくてもアップグレードだけで有効なサーバー集合が広がりうる変更で、`managed-mcp.json` と `allowedMcpServers` を併用して絞り込んでいる環境では、上げる前に `deniedMcpServers` 側の手当てが要るかを確認しておくのが無難です。

**新機能**

- 管理設定 `managedMcpServers` が加わり、組織が全ユーザーへ HTTP/SSE の MCP サーバーを配れるようになりました（詳細はハイライト 5 参照）
- `--permission-prompts none` が加わりました。無人のヘッドレスホスト向けで、**確認を出すはずの操作が自動的に拒否される**一方、有効な権限モード（auto モードを含む）はそのまま判断を続けます
- `glab mr` の `create` / `merge` / `close` / `reopen` / `note` / `update` が認識されるようになり、GitLab のマージリクエストが折り畳まれたツール要約に `MR !N` として表示され、フッターの MR バッジも更新されるようになりました
- `claude plugin validate` に `--json` が加わり、機械可読な検証レポートを出せるようになりました（詳細はハイライト 4 参照）— [English](https://code.claude.com/docs/en/plugins-reference#plugin-validate)
- VS Code 拡張のセッション一覧サイドバーに **Active のクイックフィルター**と、**Needs input / Working / Completed** のステータスフィルターメニューが加わりました

**機能改善**

- PR ステータスバッジの前提が `gh` CLI から GitHub トークンに変わり、ホスト別の探索先とフッターのヒント文言が明記されました（詳細はハイライト 1 参照）— [English](https://code.claude.com/docs/en/interactive-mode#pr-review-status)
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` が止める通信に PR・MR のステータスチェックが加わり、フィーチャーフラグ取得を切ったときの影響一覧からは PR バッジの更新頻度に関する項目が削除されました（詳細はハイライト 1 参照）— [English](https://code.claude.com/docs/en/env-vars#variables)
- サブエージェントのモデル固定が独立セクションになり、設定例と `/tasks` での確認手順が加わりました（詳細はハイライト 2 参照）— [English](https://code.claude.com/docs/en/sub-agents#run-every-subagent-on-one-model)
- 画像・PDF の蓄積がキャッシュを無効にする条件と、その際の削除の粒度が明文化されました（詳細はハイライト 3 参照）— [English](https://code.claude.com/docs/en/prompt-caching#accumulating-many-images)
- 先行リクエストのプリフィックスを読める経路が 3 項目に整理され、ワークフローのファンアウトでの保留時間が「既定で最大 5 秒」と具体化されました（詳細はハイライト 3 参照）— [English](https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache)
- iOS Simulator ペインの提供対象から **ZDR（ゼロデータ保持）を有効にした Enterprise 組織という除外条件が外れました**。除外されるのは HIPAA 構成の組織のみになり、冒頭の Note とトラブルシューティングの該当項目の両方が同じ形に更新されています — [日本語](https://code.claude.com/docs/ja/desktop-ios-simulator) / [English](https://code.claude.com/docs/en/desktop-ios-simulator)
- セルフホスト実行環境のデプロイのページに、**`--kill-session-after-min` の値の選び方**の段落が加わりました。暴走セッション向けのバックストップであり、ランナーは上限に達したセッションを**まだ使っている人がいても終了させる**ため、想定される最長セッションより十分大きい値（8 時間なら `--kill-session-after-min 480`）を設定せよ、アイドルになった会話からスロットを解放したいなら代わりに `--release-idle-session-min` を使え、という内容です — [English](https://code.claude.com/docs/en/self-hosted-environments-deploy#some-sessions-don’t-count-as-idle)
- セルフホスト実行環境のリファレンスの `--kill-session-after-min` の行にも、上記の値の選び方への参照が加わりました — [English](https://code.claude.com/docs/en/self-hosted-environments-reference#runner-cli-flags)
- 長い応答でのターミナルのリサイズと初回描画の性能が改善されました。テキストの計測結果を再利用するようになっています
- `/workflows` のエージェント詳細で、JSON の結果が構文色付き・実際の改行付きで整形表示されるようになり、長い結果は展開トグルの裏に折り畳まれるようになりました
- ヘッドレス／SDK セッションの開始が改善され、MCP サーバーの接続完了時に最初のターンが最大 50 ミリ秒早く始まるようになりました
- `/install-github-app` が、GitLab リポジトリの中で実行された場合に GitHub 専用であることを説明し、GitLab の CI/CD ドキュメントを案内するようになりました
- 入れ子になったバックグラウンドサブエージェントの結果が親サブエージェントのトランスクリプトに保存されるようになり、再開したサブエージェントがそれを保持し、共有したトランスクリプトにも受け渡しが現れるようになりました
- `allowedMcpServers` の適用範囲がユーザー追加のサーバーのみに変わりました（詳細はハイライト 5 参照）

**バグ修正**

- 同時実行しているセッションが互いの `~/.claude.json` の変更を黙って巻き戻す問題を修正。多数のセッションを同時に動かしてもワークスペースの信頼設定がリセットされず、MCP とプロジェクトの状態も失われなくなりました
- 思考が一度拒否された会話が、以降の全ターンで拒否され続ける問題を修正
- Bash の `Read()` 拒否ルールが、**オプションの値として渡されたファイル**（`--ignore-revs-file=.env`、`-f.env`、`@file`）、`git diff` / `git grep` のファイルオペランド、`cd DIR && cat FILE` の複合コマンドを対象にしていなかった問題を修正。拒否対象のファイルを含むディレクトリに対する `grep -r` / `cp -r` は確認を求めるようになりました
- テレメトリを無効にしたセッションで OAuth トークンが更新されるとプロンプトキャッシュが無効になる問題を修正
- 数百回のツール呼び出しを伴う長いターンのあと、フルスクリーンモードで会話が空白表示になる問題を修正
- コマンドやスキルの frontmatter の `model:` が指定したモデルを auto モードが対応していない場合に、そのモデルでターンを実行してしまう問題を修正。セッションのモデルを維持するようになりました
- Claude Code が認識しないモデルバージョンの Vertex 形式のモデル ID（`@YYYYMMDD` サフィックス付き）について、`CLAUDE_CODE_MAX_CONTEXT_TOKENS` が無視される問題を修正
- 実行中のシェルコマンドのライブ出力プレビューで、前の行が折り返されていると最新の行が隠れる問題を修正
- claude.ai ユーザーで、GitHub の接続チェックが起動のたびにバックグラウンドで走る問題を修正。結果が起動をまたいで記憶されるようになりました
- ペイロードの無い添付エントリを含む保存済みセッションで、`--resume` が失敗し `--continue` が空の会話を開く問題を修正
- カスタムコマンドとスキルの frontmatter の `model:` が対話セッションで無視される問題を修正
- 古いバージョンから継続した会話で、Artifact の公開が `unexpected parameter "note"` エラーで 1 度失敗する問題を修正
- MDM または管理設定ファイルで構成されたポリシーヘルパーが既に実行済みの場合に、管理設定の `forceRemoteSettingsRefresh` が起動時に無視される問題を修正
- `git rev-parse` が「not a git repository」以外のメッセージで失敗するマシンで、worktree の隔離がフックの作った worktree を拒否する問題を修正
- クラウドセッションからの OpenTelemetry のメトリクスとイベントに `user.email`・`organization.id`・`user.account_uuid` の属性が欠ける問題を修正
- 起動時のツール一覧取得中に切断した MCP サーバーが、エラーを報告せずツールゼロで接続済みとして表示される問題を修正
- ファイル編集の権限ダイアログで、変更行が何の表示も無く途中で切られることがある問題を修正
- 一時的な git のプローブ失敗のあと、リポジトリ検出が既知のリポジトリ識別情報を落とす問題を修正
- 管理設定ファイル・そのドロップイン・MDM の plist・HKLM の値のいずれかが解釈できないときに、管理設定が黙って未適用になる問題を修正。Claude Code が起動を拒否し、原因のソースを名指しするようになりました
- Remote Control セッションで Stop がバックグラウンドエージェントとワークフローを実際には停止しない問題を修正。停止したタスクはプロセスが終了するまで表示され続け、再度停止できるようになりました
- 停止した前回の実行がまだ終了処理中のワークフローを再開すると、そのエージェントが二重に動きうる問題を修正
- github.com のマーケットプレイスのリポジトリ URL に末尾のスラッシュや宙に浮いた `?` / `#` が付いていると、使えない `.git` のクローン URL が生成される問題を修正
- Stop フックがターンをブロックした場合に、その次のターンがそのターンのモデルの推論を失い、一部のモデルではプロンプトキャッシュを外す問題を修正
- ブラウザでホストしていた MCP サーバーのページが失われたあと、リモート（claude.ai）セッションがターン開始に 60 秒かかる問題を修正
- worktree で隔離されたセッションが、メインのチェックアウトに到達できない一般的な Bash のループ・`xargs` のパイプライン・ランチャー経由のコマンドを拒否する問題を修正
- セッションが一時停止している間にコネクターツールの権限確認が承認されると、リモートセッションとスケジュール実行セッションが何もしなくなる問題を修正

**その他**

- モデル設定ページの環境変数表で `CLAUDE_CODE_SUBAGENT_MODEL` のリンク先アンカーが更新されました。生の差分は 14 行ですが実質は 2 行で、残りは表の桁揃えです（詳細はハイライト 2 参照）— [日本語](https://code.claude.com/docs/ja/model-config#environment-variables) / [English](https://code.claude.com/docs/en/model-config#environment-variables)
- エージェントチームのページの差分は、`CLAUDE_CODE_SUBAGENT_MODEL_FORCE` のリンク先アンカーの張り替え 1 行のみです（詳細はハイライト 2 参照）— [English](https://code.claude.com/docs/en/agent-teams#specify-teammates-and-models)
- 設定リファレンスの `prUrlTemplate` から「`gh` が報告した URL」という限定が外れ、既定値の説明も短縮されました（詳細はハイライト 1 参照）— [English](https://code.claude.com/docs/en/settings-reference#prurltemplate)

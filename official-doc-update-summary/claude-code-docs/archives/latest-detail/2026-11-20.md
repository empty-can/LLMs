## 1. Enterprise Admin Console で管理する組織にサインインできるようになった

**`authentication` の「Log in to Claude Code」に、ログインの方法として「Enterprise Admin Console」の項目が加わりました。** Owner が組織のプロバイダーかゲートウェイについてこのサインインをオンにしていれば、シェルで `claude auth login` を実行し、ブラウザーで組織を選びます。サインインできたかは、ターミナルに `Signed in to the organization` が出るかで確かめます。要る Claude Code の版は、claude.com の Enterprise Admin Console のガイドの「Before you start」を見る、となっています。changelog の v2.1.330 にも、Anthropic の Enterprise Admin Console で管理する組織へのサインインを加え、`claude auth login` の後に Claude Code が組織の設定を適用して、組織のクラウドのプロバイダーかゲートウェイを使う、という項目があります。

- **`settings-reference` の新しい h3「`enforceAnthropicSignIn`」**: Anthropic の API での claude.ai のログインか、Enterprise Admin Console のサインインを求めるキー（Boolean、既定は未設定、v2.1.329 以降）。Enterprise Admin Console のサインインが数えられるのは、`forceLoginOrgUUID` が組織を名指し、`policyHelper` を設定していないときだけ。クラウドのプロバイダーかゲートウェイで動く Claude Desktop のセッションも止めるので、先にガイドの「Require the sign-in with managed settings」を読む、という注意がある。スコープは Managed で、managed settings ファイルに設定すると server-managed settings の下でも効き、MDM ポリシーもあればそちらにも設定する。server-managed settings・HKCU・policy helper の出力にあるこのキーは無視される。「Settings index」と `managedSourcesBehavior` の節にも、このキーの行と項目が加わった
- **policy helper の出力の例外**: `settings-reference` の「Write the helper output」は、helper が出す `managedSettings` を「唯一の」managed settings のソースとする言い方をやめ、MDM・ファイル・HKCU のソースを無視する例外として、`forceRemoteSettingsRefresh`（起動時の確認は helper より前に、どの管理者のソースも読む）と `enforceAnthropicSignIn`（MDM ポリシーか managed settings ファイルから読む）を挙げる形になった。`managed-settings` の「Compute the policy with a helper program」もこの例外（「a few keys」）へのリンクになった。`server-managed-settings` では、「Settings precedence」の policy helper の段落が h4「When endpoint-managed settings take over」になって「Write the helper output」へリンクし、「Enforce fail-closed startup」の policy helper の段落は外れた
- **managed settings の各ページ**: `managed-settings` の「Choose a delivery mechanism」に「Sign-in requirement」（`enforceAnthropicSignIn`）の項目が加わり、「How Claude Code combines managed sources」の冒頭に、claude.ai の **Organization settings > Desktop 3P** でプロバイダーかゲートウェイを設定したなら、先にガイドの「which settings take priority」を読む、と加わった。`server-managed-settings` の冒頭の注記にも、Desktop 3P で設定したならこのページではなくガイドに従う、と加わり、「Per-key exceptions across managed sources」に `enforceAnthropicSignIn` の項目、「Platform availability」にコンソールの設定が当てはまるときへの案内が加わった
- **ほかのページの案内**: `authentication` の「Authentication precedence」（組織が Enterprise Admin Console でプロバイダーかゲートウェイを設定し、その組織にサインインしたなら、リクエストの行き先はガイドで確かめる）、`admin-setup` の「Decide how settings reach devices」、`network-config` の「Cloud provider and LLM gateway routing」（組織にサインインする開発者は、ガイドが挙げる Anthropic のホストにも届く必要がある）
- **`errors` の「Find your error」の 8 行**: `You chose an organization that is managed in Anthropic's Enterprise Admin Console`・`The organization's settings won't apply on this computer`・`no usable organization sign-in` などはガイドの該当する節へ、`the session no longer runs under that sign-in` や `This conversation ran under organization` などの 2 行は `authentication` の「Log in to Claude Code」へ、`Claude Code could not read the managed settings that apply to this computer, which may require a sign-in to Anthropic` は `enforceAnthropicSignIn` へリンクする。ほかに、managed settings がサインインを求めるという行と、Microsoft Foundry のキーかトークンを managed settings が設定した（か、読めなかった）という行がある

同じ回に、`forceLoginMethod` と `forceLoginOrgUUID` でログインを絞る説明も改められました（下の「軽微な更新」の「機能改善」）。

## 2. プロジェクトのスレッドがリポジトリのスキルを読み込むようになった

**`claude-projects` の「What threads pick up from your repositories」で、クラウドのスレッドは各リポジトリのスキル・エージェント・コマンドを読み込める、という説明になりました。** これまでは、クラウドのスレッドは各リポジトリの `CLAUDE.md` の指示を読み込み、スキル・`.mcp.json` のサーバー・`.claude/settings.json` は読み込まない、としていました。今回は、スレッドは各リポジトリの `CLAUDE.md` の指示とともに始まり、`.mcp.json` のサーバーと、`.claude/settings.json` のフック・権限のルール・`env` は読み込まない、となっています。表も、「`.claude/skills/` のスキル」（読み込まない。claude.ai のアカウントで有効にする）と「`.claude/` のエージェントとコマンド」（読み込まない。スレッドを自分のコンピューターで動かす）の 2 行が、「`.claude/` のスキル・エージェント・コマンド」（スキップするスレッドを除き、すべてのリポジトリから読み込む）の 1 行になりました。`CLAUDE.md` の行も、「サブディレクトリーの `CLAUDE.md` とパス別のルールは読み込まない」から「パス別のルールは開始時には読み込まない」になっています。

新しい h4「Threads that skip repository skills」は、クラウドのスレッドがリポジトリのスキル・エージェント・コマンドを読み込まない場合として、次のようなものを挙げます。

- **古いスレッド**: 2026年10月01日より前に始まったスレッドなら、新しいスレッドを始めるよう Claude に頼む
- **名前がドットで始まるリポジトリ**: `.github` のように、スレッドのリポジトリのどれかがそうなら、スレッドを Remote Control のセッションとして動かす。スキルなら、claude.ai のアカウントで有効にしてもよい
- **セルフホストの環境**: スキル・エージェント・コマンドをランナーのイメージに加える

同じページの「How a project is organized」「Decide which repositories to add」も、読み込まないものを「スキル・`.claude/settings.json`・`.mcp.json`」ではなく「`.mcp.json` のサーバーと `.claude/settings.json` のフック・権限のルール・`env`」とする言い方に改められました。「Get skills, plugins, connectors, and tools into threads」の Skills の項目も、リポジトリの `.claude/skills/` にコミットしたスキルはクラウドのスレッドで読み込まない、という文が、リポジトリにコミットしたスキルは「What threads pick up from your repositories」を見る、という案内になっています。「Open a thread when you need control」の、スレッドを開いてできることは「Claude がしたことを 1 段ずつ読む」から「Claude のメッセージを読み、スレッドが今していることを見る」になり、Esc で割り込む方法は外れて **Stop** だけになっています。「A thread looks stuck」も、トランスクリプトを読む、から、スレッドが今していることを見る、になりました。

ほかのページもこれに合わせて改められています。

- **`skills`**: 「Choose where skills load」の表の Project と Nested の行から、プロジェクトのクラウドのスレッドでは読み込まない、という部分が外れ、プロジェクトのクラウドのスレッドについては、どのスレッドが読み込むかを確かめる、となった。「Use skills in Cowork and cloud sessions」からも、プロジェクトのクラウドのスレッドではリポジトリの `.claude/skills/` のスキルが使えない、という文が外れ、リポジトリにスキルをコミットする方法が「プロジェクトのスレッド以外のクラウドのセッション」に限られなくなった
- **`routines`**: 「Create a scheduled task」で、セッションが使うスキルにクローンしたリポジトリにコミットしたものが含まれる、という文から「プロジェクトのスレッドの外では」という限定が外れ、プロジェクトのタスクなら、どのスレッドが読み込むかを確かめる、となった
- **`cloud-environments`**: 「What carries over from your setup」の注記が、プロジェクトのクラウドのスレッドはリポジトリのルートの `CLAUDE.md` などだけを読み込む、から、`.mcp.json` のサーバーと `.claude/settings.json` のフックと権限のルールなしで始まり、スキル・エージェント・コマンドを飛ばすことがある、になった
- **`claude-code-on-the-web`**: 「Manage context」に h4「Use subagents and agent teams」ができ、リポジトリの `.claude/agents/` で定義したサブエージェントは自動で読み込まれ、プロジェクトではどのスレッドが読み込むかを確かめる、となった（これまでは、プロジェクトのスレッドの外では自動で読み込まれる、としていた）

## 3. リンクできる GitHub のアカウントを絞れるようになった

**`admin-setup` の「Connected GitHub accounts」に h4「Limit which GitHub accounts can be linked」ができました。** Claude の組織にリンクできる github.com の組織と個人のアカウントを絞るには、承認するものを許可し、**Only allowed accounts can be linked** をオンにします。たとえば `example-corp` だけを許可すると、メンバーも Owner も、メンバーの個人のアカウントをリンクできません。すでにリンクしたアカウントは、許可されていなくても、リンクを外すまで動き続けます。

アカウントをリンクすると、Claude は Code Review や Claude Tag のような機能のために、Claude GitHub App としてそのリポジトリで動けます。設定がオンでもメンバーは GitHub を Claude に接続でき、メンバー自身のクラウドのセッションは各メンバーの GitHub のアクセスを使うので、それらのセッションが届くリポジトリを絞るのにこの設定に頼らない、という注意もあります。手順は次の 5 つです。

1. **組織を許可する**: Team か Enterprise のプランの Owner として、ブラウザーで **Organization settings > Git providers** の GitHub の節を開き、**Choose organizations** をクリックする。表で承認する組織を選んで **Allow** をクリックする。自動では許可されないので、すでにリンクしている組織も含める
2. **ほかのアカウントを名前で許可する**: 個人のアカウントか表にない組織は、**Allow by name** をクリックして GitHub のユーザー名か組織の名前を入れる。求められたら先に自分の GitHub のアカウントを接続する（このプロンプトからの接続では、どのアカウントもリンクされない）
3. **設定をオンにする**: 表の上の **Only allowed accounts can be linked**（既定はオフ）をオンにする
4. **承認しないアカウントのリンクを外す**: リンクを外すと、Code Review のような機能はそのリポジトリでこの Claude の組織のために動かなくなり、Claude のエージェントの ID がそれらのリポジトリで動かすスケジュールされたタスクはオフになる。メンバー自身のクラウドのスケジュールされたタスクはオンのまま。許可されていないアカウントは、組織なら **Not allowed**、個人のアカウントなら **Linked personal accounts** を開いて見て、外すものを選んで **Unlink** を、残すものは **Allow** をクリックする
5. **許可したアカウントをリンクしてもらう**: 許可したアカウントが **Not linked** なら、GitHub でそれを持つ人に、Owner かメンバーの接続でリンクしてもらう。メンバーの接続なら、先にそのアカウントに Claude GitHub App を入れてもらう

許可の一覧から外してリンクを保つには、**Allowed** の下で選んで **Disallow** をクリックします。許可したアカウントのリンクを外すと、許可の一覧からも外れます。

同じ節では、**Not linked** の行は自分の GitHub のサインインから「来る」ではなく「来ることがある」となり、リンクを外した後の説明も、リンクできるアカウントを絞らない限り、次にその所有者の 1 人が GitHub を Claude に接続するとまたリンクされる、という形になりました。承認していないアカウントへの新しいリンクを止めるか、アプリを外さずにアカウントのリンクを外したままにするには、リンクできるアカウントを絞る、という注記も加わっています。

## 4. グラフを描く組み込みの mod が載った

**`plugins/mods/overview` の「Mods built into Claude Code」の表に `cc-plugin-easel` の行が加わりました。** Claude にグラフを描くツールを与え、Prometheus の範囲のクエリーの結果のような、対応する時系列の形の MCP の結果の下にグラフを自動で描く mod です。要件を満たすセッションで有効になり、`/plugin` で無効にできます。自動のグラフだけを止めるには、`/config` の **Auto charts** をオフにします。

新しい h3「Check the charts mod requirements」は、`cc-plugin-easel` が `/plugin` にないときに確かめる要件として、次のものを挙げます（要件は「これらを含む」という書き方です）。

- **サインイン**: claude.ai のサブスクリプション
- **版**: Claude Code v2.1.321 以降。Team と Enterprise は v2.1.326 以降
- **プラットフォーム**: macOS か、WSL の外の Linux

changelog の v2.1.330 には、頼まれたときと MCP のメトリクスの結果の下にグラフを描く組み込みの mod の easel を、macOS と Linux の Pro・Max と、使えるところでは Team・Enterprise に加え、自動のグラフは `/config` でオフにできる、という項目があります。同じリリースのバグ修正には、Code Mode で Claude が組み込みのグラフのツールを呼ぶと失敗する問題と、MCP の許可リストか拒否リストが組み込みのグラフのツールを除くと起動のたびに `MCP server blocked by enterprise policy: easel` の警告が出る問題（ツールは止まったまま）の修正もあります。

同じページの「Where mods run」も改められました。

- 冒頭の段落から、フックは「プラグインを読み込むどの種類のセッションでも」動く、という部分と、描画はターミナル・Desktop アプリ・VS Code の拡張機能に限られる、という文が外れた
- Desktop アプリの Code のタブの行の除外に、WSL のセッションに加えて SSH のセッションが入り、「自分のコンピューターにだけ入れた mod の、Desktop アプリの SSH のセッション」の行（Desktop がフックをリモートのマシンに写さないので、フックも描画も動かない）が加わった
- クラウドのセッションの描画の列が「No」から「Not in every session」になった

`plugins/mods/overview` は `llms-full.txt` に 2 回載っているので、これらの変更も 2 か所に出ています。

## 5. VS Code に /fork と 3 つの設定が加わった

**`vs-code` に、v2.1.330 以降で使える 2 つのコマンドと 3 つの設定などが載りました。** changelog の v2.1.330 の [VSCode] の追加に、ページが追従した形です。

- **`/fork`**（「Rewind with checkpoints」）: Claude が応答を終えたら、プロンプトの欄に `/fork` と入れると、最新のメッセージからフォークする。`/fork try the other approach` のように加えたテキストは、送られないままフォークのプロンプトの欄で待つ
- **`/workflows`**（「Use the prompt box」）: エージェントの数が出ていないときにマップを開くには、`/tasks` に加えて `/workflows` も入れられる、となった（入れる `/workflows` は v2.1.330 以降）
- **`escapeStopsClaude`**（既定は `true`）: ターンの途中で `Esc` で Claude を止める。オフなら代わりに **Stop** をクリックする。`Esc` は、メニューを閉じることと、許可の要求と質問を断ることには引き続き使える。「Use the prompt box」の、Claude を止めるとターンが終わりバックグラウンドのエージェントは動き続ける、という説明も、「**Stop** をクリックするか `Esc` を押すと」から「Claude を止めると」になった
- **`pinPrompt`**（既定は `true`）: Claude の返答をスクロールする間、自分のメッセージを上に固定する
- **`contextUsageThreshold`**（既定は `50`）: コンテキストの使用がこの割合を超えると、コンテキストの表示を出す。「Use the prompt box」の Context indicator も、使用が `contextUsageThreshold`（既定は 50%）を超えると表示する、となり、Prompt cache clock の時計のアイコンの位置は「コンテキストの表示の横」から「プロンプトの欄の中」になった
- **Open in Side Bar の `prompt`**（「VS Code commands and shortcuts」）: 新しい会話を前もって埋めるには、`"args": { "prompt": "Review this file" }` を付けて `claude-vscode.sidebar.open` にキーを割り当てる

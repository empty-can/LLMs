## 1. Agent SDK のスキルページ全面改稿とコマンド解説の統合

Agent SDK のスキルのページが、タイトルを **Agent Skills in the SDK** から **Extend agents with skills** に改め、ほぼ全面的に書き直されました。同時に **Slash Commands in the SDK**（`agent-sdk/slash-commands`）のページが削除され、その内容が新設の **Commands in Agent SDK sessions** 節として統合されています。今回の対象期間で削除されたページはこの 1 ページだけです。統合先の節では、コマンドの実体を「組み込みコマンド」「バンドルされたスキル」「自作のスキル」「`.claude/commands/` の旧来のコマンドファイル」の 4 種類に整理したうえで、`system/init` メッセージの `slash_commands` からの一覧取得、プロンプトに `/<name>` を書くだけのディスパッチ、`/compact` と `/clear` の実例が置かれました。ディスパッチは `skills` オプションに依存しないため、リストに載せていないスキルでも `/<name>` で実行できることが明記されています。

スキル側の記述も整理されました。`skills` オプションは「有効化するもの」ではなく「Claude が呼び出せる範囲を絞るもの」という言い回しに統一され、不正な名前を渡したときの挙動は **Invalid skill name error** としてトラブルシューティングへ移り、TypeScript は `Error`、Python は `ValueError` を投げるという言語別のタブになりました。旧来の **Discovering Available Skills** と **Testing Skills** の節は削除され、代わりに `security-check` スキルを作って `/security-check` で実行するまでの一連の流れと、その実行結果の例が加わっています。ツール承認の節は **Pre-approve tools for skills** に改称され、例から `permissionMode: "dontAsk"` が外れました。あわせて `SKILL.md` の `allowed-tools` フロントマターが SDK で効かないのはプロジェクト・個人のスキルの話で、claude.ai から同期したスキルは自身のフロントマターの規則に従う、という但し書きが付いています。

## 2. どのモードでも自動承認されない操作と重要なパスの明文化

権限モードのページに **Actions no mode auto-approves** という節が新設されました。`bypassPermissions` を含めどのモードでも自動承認されない操作を、明示的な ask ルールに一致するツール、組織が `ask` に設定したコネクタツール、ユーザー操作を要するツール（`AskUserQuestion` と `requiresUserInteraction` 付きの MCP ツール）、重要なパスを対象とする `rm` と `rmdir`、クロスセッションメッセージの安全策、の 5 つに整理したものです。これまで各ページが同じ内容を独自に列挙していたため、今回はそれらが軒並みこの節へのリンク 1 行に置き換わりました。権限の設定、Hooks リファレンス、Agent SDK の権限・ユーザー入力・TypeScript / Python リファレンス、サブエージェント、デスクトップ、チャンネル、サンドボックスとサンドボックス環境、非対話モードの 12 ページが対象です。

もう 1 つの新設が **Critical paths** です。これまで「ファイルシステムのルートやホームディレクトリを対象とする削除」と説明されていた回路遮断器が、対象範囲と挙動を明示した形にまとまりました。重要なパスと見なされるのは、ファイルシステムのルート、その直下のディレクトリ、ホームディレクトリ、Windows のドライブルートとその直下、作業ディレクトリとその親、そして追加の作業ディレクトリとその親（ただし `rm -rf <dir>/*` のような glob のときだけ）です。`allow` ルールでも `PreToolUse` フックの `"allow"` でも承認できず、モードごとの結果は表で示されています。PowerShell ツールを有効にしている場合の `Remove-Item` は別建ての **Remove-Item in PowerShell** に切り出され、システムパスとワイルドカードはどのモードでも問答無用で拒否、作業ディレクトリとその親への `-Recurse` はモードに従う、と 3 分類になりました。同じページには **Common setups** の表も加わり、「自分で全部レビューしたい」「CI で厳密な許可リストを使いたい」といった目的ごとに、渡すフラグと必要な隔離の組み合わせが並んでいます。

## 3. auto モード既定を前提にした入門ページの書き直し

Pro・Max・Team プランの対話セッションでは auto モードが既定の開始モードである、という前提に合わせて、入門・概念・セキュリティ系のページがまとめて書き直されました。クイックスタートは、従来の「Claude Code は変更前に承認を求めます」という手順の列挙をやめ、インストール直後の初回セッションでは各変更を確認するが、それ以降は該当プランで auto モードが既定になる、という書き方に変わっています。「Claude Code はどう動くか」のページでは権限モードの箇条書きの先頭に Auto が繰り上がり、チェックポイントの説明にあった「だから Claude は外部に副作用のあるコマンドの前に確認する」という一文が、権限モードと権限ルールで制御する、という説明に差し替えられました。

セキュリティのページは影響が大きく、「Claude Code は既定で厳格な読み取り専用の権限を使う」といった無条件の記述が軒並み「Manual モードでは」という限定付きになりました。そのうえで auto モードでは分類器が代わりに審査すること、作業ディレクトリ外の読み取りは Manual では確認を求めるが auto では確認なしに読むことが加わっています。ベストプラクティスでも、従来「プロンプトを減らす 3 つの方法」の筆頭だった auto モードが「該当プランでは既にそれが既定」という位置づけに変わり、残る 2 つ（許可リストとサンドボックス）が Manual モードでの手段として整理されました。用語集の Auto mode の項目、トラブルシューティングの索引（「セッションが auto モードで始まった」の行が追加）、機能可用性の脚注、管理者向けの設定一覧（開始する権限モードの行が追加）にも同じ趣旨が反映されています。

## 4. インタラクティブモードに 3 つの機能が加わった

**Queue messages while Claude works** の節が新設されました。Claude の作業中に入力して `Enter` を押すとターンを中断せずキューに積まれ、入力欄の上に一覧が表示されます。メッセージはツール呼び出しが終わった時点で同じターンの中で Claude に渡り、ターンが終わった時点で残っているものは次のターンとして 1 件ずつ送られます。コマンドと `!` のシェルコマンドはターンの終了まで保留され、1 つずつ実行されます。`Esc` で中断すればキューの内容がすぐ送られ、入力欄の先頭行で `Up` を押せばキューを取り消して入力欄に戻せます。

**Check spelling as you type** も新設で、v2.1.235 以降、プロンプト入力の誤字に下線を引けるようになりました。既定はオフで、`aspell`・`hunspell`・`ispell` のいずれかを自分で入れて `PATH` に通す必要があります。`spellcheck` 設定はユーザー設定・`--settings`・管理設定の 3 箇所からしか読まれず（プロジェクト設定は無視されます）、`checker`・`language`・`color` で使うプログラム・辞書・下線の色を選べます。コマンドや `@` メンション、URL、パス、フラグ、バッククォート内、数字や下線を含む語は対象外で、中国語・日本語・韓国語・タイ語などの文字も飛ばされます。下線が出ないときの切り分けとして、チェッカーが 2 回続けて落ちた場合と 15 秒超のタイムアウトが 3 回続いた場合に停止すること、`claude --debug` の `[spellcheck]` 行で原因を確認できることが書かれています。

3 つ目は **GitLab merge requests** です。v2.1.234 以降、GitLab のリモートを持つリポジトリで開いているマージリクエストがあると、GitHub の PR リンクと同じフッターの位置に `MR !N` のバッジが出ます。`glab` CLI を `PATH` に置いて `glab auth login` 済みであることが条件で、`GITLAB_TOKEN` のようなトークン環境変数は状態確認に使われません。あわせて PR レビュー状態の更新間隔の説明も書き換わり、Anthropic API かつフィーチャーフラグ取得が有効な場合は操作中でおよそ 90 秒ごと、アイドル時や端末が非フォーカスのときはより低頻度、それ以外のプロバイダーやフラグ取得が無効な場合は従来どおり 60 秒ごと、となりました。

- [Interactive mode - Claude Code Docs (English)](https://code.claude.com/docs/en/interactive-mode#check-spelling-as-you-type)

## 5. エラーリファレンスに 6 つの項目が新設された

エラーリファレンスに 6 つの節が加わりました。**Remote Control stopped because the signed-in account changed** は、Remote Control セッション中に別のターミナルで `/login` して claude.ai のアカウントや組織を切り替えたときのものです。v2.1.234 以降は切り替えが確認され次第セッションを止めるようになり、それ以前は数時間後に `HTTP 404` で失敗するまで気付けませんでした。**Sessions ended while this machine was offline** は、マシンがオフラインの間にサーバー側で Remote Control の環境が片付けられ、その中のセッションが再開できなくなった場合の通知です。**The remote sent a reply this version can't display** は、クラウドセッションにアタッチした端末で `/context` や `/btw` の応答を描画できなかったときのもので、v2.1.235 より前は生の JavaScript エラーが出ていました。

**Cannot switch renderers in this session** は `/tui` でレンダラーを切り替えられない場合です。バックグラウンドの作業が走っている場合と、再起動後のプロセスに引き継げない制限がセッションにある場合の 2 通りで、後者は括弧の中に理由が示されます。`--system-prompt` や `--tools` などの起動フラグ、フックや SDK からセッション限定で追加された deny・ask ルール、コマンドラインで表現できない規則や追加ディレクトリが該当します。**subagent\_type is required** は、Agent tool の呼び出しが `subagent_type` を省略し、かつ `general-purpose` サブエージェントが無いセッションで出ます。`CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` を設定した非対話モードと、`tools: Agent(...)` の許可リストが `general-purpose` を含まない場合の 2 つが挙げられており、v2.1.235 より前は `Agent type 'general-purpose' not found` でした。**Message too large for cross-session delivery** は、同一マシンの別セッション宛てメッセージが約 100 万文字の上限を超えた場合で、v2.1.235 より前は送信済みとして扱われ、受信側が黙って捨てていました。

既存の節も手が入りました。`Prompt is too long` は対話セッションでは `Context limit reached · /compact or /clear to continue` として表示されること、自動コンパクトをユーザー設定で切っている場合はその旨と `/config` への案内が続くことが加わりました。`Credit balance is too low` には、サブスクリプションを使うつもりが `ANTHROPIC_API_KEY` 経由になっている場合の切り分けが先頭に入り、`Anthropic profile login expired` はメッセージの 2 形態と、どちらが出るかでプロファイルの選ばれ方が分かるという説明に整理されています。

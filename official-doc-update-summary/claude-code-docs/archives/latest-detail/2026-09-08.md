## 1. 出力スタイルの変更がキャッシュ無効化の側へ移った

プロンプトキャッシングのページの見出しマップで、**`Changing output style`（出力スタイルの変更）の所属グループが入れ替わりました**。従来は `Actions that keep the cache`（キャッシュを保持する操作）の 3 番目にあり、`Editing CLAUDE.md mid-session` と `Changing permission mode` に挟まれていました。今回はそこから外れ、`Actions that invalidate the cache`（キャッシュを無効にする操作）の側、`Denying an entire tool` と `Compacting the conversation` の間に入っています。**行の移動としては追加 1 行・削除 1 行**で、このページの差分はこれだけです。

このページはグループの性格を「これらの操作は次のリクエストでキャッシュの一部またはすべてをミスする」対「これらの操作は会話の末尾に追加するか、リクエストにまったく触れない」と定義しているので、**グループ間の移動はそのまま挙動の分類が反転したことを意味します**。

ただし**本文は今回の差分に含まれていません**。現行の `llms-full.txt` の `### Changing output style` は依然として「出力スタイルはシステムプロンプトの一部で、Claude Code はセッション開始時に 1 回読む。`/config` や `outputStyle` 設定でセッション途中に変えてもキャッシュは無効にならないが、**変更も適用されない**。次の `/clear` か再起動で新しいスタイルが読み込まれる」という旧来の記述のままです。さらに `Actions that keep the cache` の導入文自身が「CLAUDE.md の編集や**出力スタイルの変更**など、一部は設定変更が再起動を待つ理由でもある」と、この節を保持側の代表例として名指ししています。**つまり本文側は 2 か所とも旧分類を前提にしたままで、次回以降の書き換えが避けられない状態**です。

分類が変わった以上、少なくとも「セッション途中の変更がキャッシュを無効にする」ようになったと読めますが、**それが「変更が途中でも適用されるようになった」ことまで含むのかは、本文が届くまで断定できません**。キャッシュを無効にするということはシステムプロンプトが作り直されるということなので、適用もされる方向の変更である可能性は高いものの、今回の差分にその根拠はありません。

## 2. スキルの読み込み先を選ぶ節が新設され配下が全面改称された

スキルのページは今回**唯一まとまった構造変更があったページ**で、見出しマップの差分 19 行のうち 11 行（追加 6・削除 5）を占めます。見出しマップのインデントは 0 段が h2・2 段が h3・4 段が h4 に対応しており、その対応で読むと次のようになります。

**従来**は h2 `Getting started`（はじめに）の下に h3 が 3 つ（`Create your first skill` / `Where skills live` / `Skills synced from claude.ai`）と `Remove a skill` が並び、`Where skills live` の配下に h4 が 4 つ（`Live change detection` / `Discovery from parent and nested directories` / `Skills from additional directories` / `Skills in Cowork and cloud sessions`）ぶら下がる構成でした。これは現行の `llms-full.txt` の構造と一致します。

**今回**、`Where skills live`（スキルが存在する場所）が h3 から **h2 `Choose where skills load`（スキルの読み込み先を選ぶ）へ昇格**し、`Getting started` に残るのは `Create your first skill` だけになりました。配下だった 4 つの h4 は**そのまま h3 へ 1 段上がり、名前も付け替えられています**。

| 従来（h4） | 今回（h3） |
|---|---|
| `Live change detection` | （**削除**） |
| `Discovery from parent and nested directories` | `Load skills in monorepos and subdirectories` |
| `Skills from additional directories` | `Load skills from a directory outside the project` |
| （なし） | `Resolve skills that share a name`（**新設**） |
| `Skills in Cowork and cloud sessions` | `Use skills in Cowork and cloud sessions` |

改称はいずれも**「どこに置かれるか」を説明する名詞句から、「どう読み込ませるか」を指示する動詞句へ**という一貫した向きです。`Discovery from parent and nested directories` → `Load skills in monorepos and subdirectories` は、現行本文がまさにモノレポの例（`packages/frontend/.claude/skills/`）で説明している内容なので、**用途を見出しに引き上げた改称**と読めます。`Skills from additional directories` → `Load skills from a directory outside the project` も同様に、`--add-dir` という手段ではなく「プロジェクト外から読む」という目的を名前にした形です。

**新設は 2 つ**です。`Resolve skills that share a name`（名前が衝突するスキルを解決する）に相当する内容は、現行本文では `Where skills live` の地の文に埋もれています ―― enterprise > personal > project の優先順位、ネストされたスキルが `apps/web:deploy` のようなディレクトリ修飾名で共存すること、`/deploy` と `/apps/web:deploy` の使い分け。**これらが独立した節に切り出されるものと見られます**が、内容が加わるのか整理だけなのかは本文が来るまでわかりません。`Edit a skill during a session`（セッション中にスキルを編集する）は、削除された `Live change detection`（ライブ変更検出）と入れ替わる位置にありますが、**同じ内容の改称なのか別物なのかは見出しからは判断できません**。`Live change detection` の現行本文は「スキルディレクトリのファイル変更を監視し、追加・編集・削除が再起動なしで現在のセッションに効く」というもので、`Edit a skill during a session` はその挙動を利用者の動作の側から言い直した名前に見えますが、**根拠は名前の類似だけ**です。なお `Edit a skill during a session` は `Skills synced from claude.ai` の後・`Remove a skill` の前という、元の `Live change detection` とは異なる位置に置かれています。

構造上もう 1 点、**`Skills synced from claude.ai`（4 つの h4 を含む）と `Remove a skill` は行そのものが無変更のまま、所属する h2 だけが `Getting started` から `Choose where skills load` へ移りました**。見出しマップはこれらの行に差分を出しませんが、直前の h2 が変わっているため、ページ構成としては移動しています。

## 3. 設定ページと設定リファレンスのタイトルが入れ替わった

`llms.txt` の差分は 4 行だけで、その全部が **`Settings` セクションの 2 ページのタイトル**です。

- `settings.md`: `Claude Code settings` → **`Settings files and precedence`**（設定ファイルと優先順位）
- `settings-reference.md`: `Claude Code settings reference` → **`All settings`**（全設定）

**説明文（`:` 以降）はどちらも 1 文字も変わっていません**。`settings` 側は従来どおり「設定を変更し、キーが属すべきスコープを選び、変更を検証し、複数箇所で設定されたときにどの値が使われるかを学ぶ」、`settings-reference` 側は「すべての `settings.json` キーの完全なリファレンス。それぞれの置き場所・型・既定値と、貼り付けられる例、そして全キーの索引つき」です。つまり**ページの中身の説明はそのままで、呼び名だけが差し替わりました**。

あわせて見出しマップ側で、**`settings-reference` の先頭 h2 `All settings` が `Settings index`（設定の索引）に改称**されています。2 つを重ねると意図が見えます ―― これまで `All settings` はリファレンスページ内の 1 節（全キーを 1 表に並べた索引）の名前でしたが、**その呼称がページ全体のタイトルへ繰り上がり、節の側は実態どおり「索引」と名乗るようになった**形です。`settings` 側が `Settings files and precedence` になったのも、2 ページの役割分担（ファイルの置き場所と優先順位を扱う側 / キーを網羅する側）をタイトルだけで見分けられるようにする狙いと読めます。

**本サマリの参考リンクのタイトルは、この新しい名前に従っています。** ページ本文（`llms-full.txt`）側は無差分なので、`settings-reference` の h2 は現時点でも `## All settings` のままです。

- [All settings - Claude Code Docs (English)](https://code.claude.com/docs/en/settings-reference)
- [Settings files and precedence - Claude Code Docs (English)](https://code.claude.com/docs/en/settings)

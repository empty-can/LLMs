## 1. 新しいセッションの既定モデルを指定する環境変数

`ANTHROPIC_DEFAULT_MODEL` が加わりました。新しいセッションが既定で始まるモデルをエイリアスまたはモデル名で指定するもので、Claude Code v2.1.236 以降が必要です。**Set a default model for new sessions** の節が新設され、モデルの決め方の優先順位の一覧にも 5 番目として加わりました。

既存の変数との違いは、ユーザーの選択との関係です。この変数が効くのは、`--model` フラグ・`ANTHROPIC_MODEL`・設定ファイルの `model`（`/model` で保存した選択を含む）・組織の既定モデルのいずれもモデルを決めていない場合だけです。`/model` で保存した選択はその後の起動でもこの変数より優先されます。`ANTHROPIC_MODEL` を設定していた場合は逆で、`/model` で何を保存しても次の起動ではその変数のモデルに戻ります。つまり `ANTHROPIC_DEFAULT_MODEL` は「始点」を決めるだけで、ユーザーの上書きを奪いません。`/model` のピッカーでは、Default の行にこの変数が効いていることを示す `Set by ANTHROPIC_DEFAULT_MODEL` のラベルが出ます。

無視される場合も列挙されました。値が `default`・`inherit`・`opusplan`・`haiku` のとき、`enforceAvailableModels` が有効なとき、`availableModels` や組織のモデル制限がそのモデルを除外しているとき、アカウントでそのモデルが使えないときです。セッションの再開の扱いも独特で、新しいセッションがこの変数のモデルで始まる状況では、`claude --resume`・`--continue`・`/resume` で再開したセッションもこの変数のモデルで始まり、トランスクリプトに保存されたモデルは復元されません。あわせて、環境変数と設定キーの両方がある場合は環境変数が優先されるという `env-vars` の原則にも、この変数だけは例外だという但し書きが付きました。

## 2. ファイルの変更を書き手によらず捕捉する FileChanged フックの拡充

`FileChanged` の節が大幅に加筆され、ページ内の他のイベントからの誘導も整備されました。この節はこれまで「監視対象のファイルがディスク上で変わったときに動く」という 1 文だけでしたが、Claude Code はツール呼び出しではなくファイルシステムのウォッチャーで検知するため、`Edit` や `Write` のツール呼び出しでも、Claude が `Bash` で走らせたスクリプトでも、Claude Code の外のプロセスでも同じように発火する、という説明に変わりました。

`PreToolUse` と `PostToolUse` の側からも誘導が入りました。`PreToolUse` には、特定のファイルの変更を捕まえたいならツール名でのマッチではなく `FileChanged` を使うこと、ただし FileChanged は変更の後に動き決定権も無いので書き込みを止められないことが加わっています。`PostToolUse` には、マッチャーを省略するか `"*"` にすれば全てのツールの成功後に動くこと、その場合はフック側で `git status --porcelain` などを使って何が変わったかを自分で調べればよいこと（`git diff` では追跡されていないファイルを取りこぼす）、失敗したツール呼び出しには `PostToolUseFailure` に同じフックを足すこと、そして `Bash` コマンドや外部プロセスが同じファイルを書き換えたときには `Edit|Write` にマッチする `PostToolUse` は動かないことが書かれました。

実例も加わりました。`data.csv` の改行コードを変更のたびに正規化する `FileChanged` フックの設定と、そのシェルスクリプトです。スクリプトは標準入力の JSON の `file_path` から絶対パスを読み、`grep` で行末の CR を確かめてから `perl -pi` で除去します。この `grep` のガードが緩いと無限ループになる、という注意が添えられました。`perl -i` は置換が起きなくてもファイルを書き直すため、Claude Code が毎回フックを動かし直してしまうからです。監視対象を事前に列挙できない場合に `watchPaths` を返して動的に増やすやり方も加わりました。ウォッチャーは誰かが監視対象のファイルを名指しするまで起動しないため、少なくとも 1 ファイルを名指しする FileChanged グループか、`SessionStart` / `CwdChanged` のフックで最初の一覧を与える必要があります。動的なパスを扱うグループはマッチャーを省略します（`"*"` も全ファイルにマッチしますが、`*` という名前のリテラルなファイルとして監視リストに登録されてしまいます）。

- [Automate actions with hooks - Claude Code Docs (English)](https://code.claude.com/docs/en/hooks-guide#auto-format-code-after-edits)

## 3. スキルやサブエージェントのフロントマターを検証する手順の整備

`claude plugin validate` の使い方が **Validate a plugin or a directory without a manifest** としてまとまりました。フロントマターが壊れているスキル・サブエージェント・コマンドのファイルを見つけるには、それらを置いているディレクトリを名指しして実行します。Claude Code は名指ししたディレクトリの外を見ません。`plugin.json` を持つプラグインに対する実行を除き、Claude Code v2.1.233 以降が必要です。

何を調べたいかで指定先が変わる、という表が新設されました。`plugin.json` を持つプラグインなら、そのプラグインのディレクトリを指定して `plugin.json`・`hooks/hooks.json`・プラグイン直下の `skills`・`agents`・`commands` を調べます。`plugin.json` がまだ無い場合など、スキル・サブエージェント・コマンドのディレクトリ 1 つを調べたいなら `.claude/skills` や `~/.claude/agents` のように直接指定します。プロジェクトの 3 ディレクトリをまとめて調べるなら `.claude` を、ユーザーレベルなら `~/.claude` を指定します。フォルダ直下の `SKILL.md` を調べるには、そのフォルダを収めている `skills` という名前のディレクトリを指定する必要があり、`plugins/` のような別名の下にあるものは調べる手段がない、という制約も明記されました。シンボリックリンクは辿らず、リンクがどこにあるかで警告になるかエラーになるかが変わることも 3 通りに整理されています。

サブエージェント側にも **Subagent files Claude Code skips** が新設されました。Claude Code がセッション中に何も知らせずに読み飛ばすのは、フロントマターに `name` が無い場合（そばに置いた説明文書として扱われます）、`name` が `-` で始まるか `:` を含む場合、`name` があって `description` が無い場合、YAML が解析できない場合の 4 つです。最初のもの以外は `--debug` のデバッグログに理由が書かれます。プラグインのサブエージェントは例外で、`name` が無くても解析に失敗してもファイル名で読み込まれます。あわせて、プラグインのリファレンスの「よくある問題」の表とマーケットプレイスの検証エラーの表も、この新設節へ誘導する形に書き換わりました。検証エラーの表からは、マーケットプレイスのディレクトリからは調べられない `YAML frontmatter failed to parse` と `hooks.json` の 2 行が外れ、代わりに `No manifest found in directory` の行が入っています。

- [Create custom subagents - Claude Code Docs (English)](https://code.claude.com/docs/en/sub-agents#subagent-files-claude-code-skips)

## 4. プロジェクトディレクトリ名を自分で決める設定の全面的な解説

前回の対象期間に changelog で名前だけ告知された `CLAUDE_CODE_PROJECT_DIR_NAME` に、**Name the project directory yourself** という専用の節ができました。既定ではトランスクリプトの保存先の `<project>` の名前は作業ディレクトリのパス全体から導かれますが、`CLAUDE_CONFIG_DIR` と並べてこの変数を設定すると、そのセッションのトランスクリプトと自動メモリを自分で決めた名前の下に置けます。Claude Code を組み込んでセッションごとに設定ディレクトリを分けるホスト向けで、v2.1.234 以降が必要です。`CLAUDE_CONFIG_DIR=/srv/tenant-a CLAUDE_CODE_PROJECT_DIR_NAME=work claude` で起動すると、作業ディレクトリが何であれ `/srv/tenant-a/projects/work/` に書かれます。

守るべき規則が 3 つ挙げられました。名前は作業ディレクトリによって変わらないため、既定の `~/.claude` の下では全プロジェクトのトランスクリプトが 1 つに混ざってしまいます。そのため `CLAUDE_CONFIG_DIR` が未設定なら Claude Code はこの変数を無視します。名前は英数字・ハイフン・アンダースコアで 1〜64 文字とし、`con` のような Windows のデバイス名は使えません。それ以外の値は無視され、導出された名前に戻ります。そして `claude` を起動するシェルの環境で設定する必要があります。起動時に一度だけそこから読むため、設定ファイルの `env` ブロックでは指定できません。一度この名前で使い始めたら以後も同じ名前で起動すること、名前を付けずに起動すると導出された方のディレクトリを読み書きすることも書かれました。ただし保存済みのセッションが消えるわけではなく、セッションピッカーで `Ctrl+A` を押せばその設定ディレクトリ配下の全プロジェクトディレクトリのセッションが並び、`claude --resume <session-id>` はどちらの名前で保存されたセッションも見つけます。

参照は 7 ページに広がりました。自動メモリのページには、この変数を設定するとリポジトリに関わらずその名前のディレクトリが使われるため、その設定ディレクトリで起動したプロジェクトが 1 つの自動メモリを共有することが加わりました。環境変数のページには一覧の表にこの変数の行が新設され、設定のページの `env` の説明には、Claude Code が起動環境からしか読まないこの変数を `env` ブロックからは無視する（v2.1.234 以降）ことが加わっています。Agent SDK 側では、マルチテナントの隔離の手順に「設定ディレクトリが作業ディレクトリ 1 つに対応するならトランスクリプトのパスを短く保つために併用できる」（TypeScript Agent SDK v0.3.234 以降）、外部ストレージへの永続化のページに `projectKey` がこの名前でキーされるようになる旨、セッションのページに保存先を探すときの読み替えが、それぞれ加わりました。

- [Manage sessions - Claude Code Docs (English)](https://code.claude.com/docs/en/sessions#name-the-project-directory-yourself)
- [Environment variables - Claude Code Docs (English)](https://code.claude.com/docs/en/env-vars#variables)

## 5. 出力リダイレクトの宛先がファイル書き込みとして検査される

権限のページの Bash の節に **Redirections** が新設されました。`>`・`>>`・`2>` のような出力リダイレクトの宛先を、Claude Code はファイルへの書き込みとして検査します。検査の対象は `Edit` の allow・deny ルール、保護されたパス、作業ディレクトリです。`Bash(git commit *)` のようなルールが許すのはコマンドであって宛先ではない、という点が明示されました。`/dev/null` は検査されません。`~` で始まる宛先やグロブ文字を含む宛先は承認が要ります。読み取り専用コマンドの説明にも、`ls > out.txt` のようなリダイレクトは宛先の検査が加わる、という 1 行の誘導が入りました。

同じページの冒頭にも、権限プロンプトの選択肢に関する説明が加わりました。ときどき「今後は聞かない」もセッション中の許可も出ず、1 回限りの承認しか選べないプロンプトがあります。Claude Code がそれらの選択肢を出すのは、その選択肢が何を許すことになるかをプロンプト上で全て見せられるときだけだからです。コマンドや編集内容が大きすぎて全部を表示できない場合や、選択肢のラベルにルールが対象とする全てのコマンド・パスを収められない場合には選択肢が省かれます。その場合は 1 回だけ承認するか、`/permissions` で自分でルールを足すよう案内されています。

- [Configure permissions - Claude Code Docs (English)](https://code.claude.com/docs/en/permissions#redirections)
- [Configure permissions - Claude Code Docs (English)](https://code.claude.com/docs/en/permissions#permission-system)

## 1. モデル設定

追加 48 行・削除 17 行。新設された **Set a default model for new sessions** はハイライト 1 のとおりです。それに伴って、ページ中に散っていた「Default はどう決まるか」の記述がまとめて書き直されました。

書き換えの向きは、各所の説明を 1 箇所へ寄せることです。`default` エイリアスの表の行は、アカウントタイプの推奨モデルと組織の既定モデルを並べて説明していたものが、`#default-model-setting` の「アカウントの実行時既定」への参照 1 つになりました。`availableModels` の **Default model behavior** も、`enforceAvailableModels` を併用しない限り Default はアカウントの実行時既定のまま、という言い方に整理されています。組織の既定モデルの節でも、「Default はアカウントタイプの既定の代わりにそのモデルになる」から「Default はそのモデルになる」へ、また「他のモデル選択は全て優先される」から「次の選択が優先される」へと、限定を外したり具体化したりする修正が入りました。組織の既定がアカウントで使えない場合の帰着先も、「アカウントタイプの既定」ではなく「組織の既定が無かった場合と同じ解決」に直っています。`availableModels` と `enforceAvailableModels` を組み合わせる例の説明も、`enforceAvailableModels` も `env` ブロックも無い場合に Default を選ぶと「そのティアの最新リリースになる」だったものが「実行時既定になる」に変わりました。

エフォートに関する追記もあります。Remote Control でつないだ電話やブラウザのエフォート操作から選んだ水準は、そのセッション限りで、保存された既定は変わりません。エフォートの変え方の一覧にも、接続したデバイスから選ぶ選択肢が Claude Code v2.1.234 以降として加わりました。ほかに、認識できないモデル ID のコンテキスト管理の説明で、API が返す「長すぎる」エラーが「Claude Code が認識できる形のもの」に限られることが明示され、ゲートウェイが文言を書き換えた場合は復旧が動かない、という書き方に直っています。エイリアス変数の表の導入文にも、この表には `ANTHROPIC_DEFAULT_MODEL` を載せていない旨の断りが付きました。

## 1. Code タブで効き方が変わる Claude Code の設定キーの表が desktop に載った

**`desktop` の「Enterprise configuration」の「Managed settings」の下に、h4「Claude Code settings that behave differently in the Code tab」ができました。** ローカルのセッションでは Code タブがターミナルの画面の代わりになるため、ここに挙がったキーなどは効き方が変わるか目に見える効果がない、ターミナルでは引き続き効くので設定したままでよい、という前置きの後に、キーとローカルのセッションでの扱いの表（15 行）が続きます。前置きは「among others」と断っているので、表のキーですべてではありません。

- `askUserQuestionTimeout`: タイムアウトは効かず、Claude からの質問はユーザーが答えるまで開いたまま
- `awaySummaryEnabled`: 効果がない
- `bashEditDiffEnabled`: Bash のコマンドが変えたファイルの一覧を Code タブは示さない
- `companyAnnouncements`: Code タブはお知らせを示さない
- `defaultShell`: ユーザーが `!` の後に打ったコマンドは、アプリが選ぶシェル（macOS と Linux ではログインシェル、Windows では PowerShell）で動く
- `fileSuggestion`: `@` のファイルピッカーは自分でファイルの一覧を作り、設定したコマンドを動かさない
- `modelPicker`: モデルピッカーは各ユーザーのアカウントで使えるモデルを並べる。絞るには `availableModels` を設定する
- `pluginTrustMessage`: プラグインを入れるときにユーザーが見る警告に、設定したメッセージが入らない
- `prUrlTemplate`: プルリクエストのリンクは、テンプレートではなくプルリクエスト自身の URL を使う
- `respectGitignore`: `@` のファイルピッカーは自分でファイルの一覧を作り、このキーを読まない
- `respondToBashCommands`: 値にかかわらず、ユーザーが `!` で動かしたコマンドの出力に Claude が応答する
- `showClearContextOnPlanAccept`: plan を承認するときに、コンテキストをクリアする選択肢が出ない
- `skipDangerousModePermissionPrompt`: Code タブは Bypass permissions モードに独自の確認を持ち、このキーではそれを飛ばせない
- `verbose`・`viewMode`（1 行）: 表示は各ユーザーがセッションのメニューの **Transcript view** で選ぶ
- `worktree.baseRef`・`worktree.sparsePaths`・`worktree.symlinkDirectories`（1 行）: Code タブがセッションのために作る worktree には使われない

同じページの「Coming from the CLI?」の「Shared configuration」でも、`settings.json` の設定が Desktop のセッションに効くという項目の末尾に、一部のキーは Code タブで効き方が変わる、という文とこの h4 へのリンクが加わりました。表のキーはどれも `settings-reference` に前から載っているもので、新しいキーではありません。changelog に対応する項目はありません。

## 2. Claude Desktop の SSH セッションの記述が 4 か所補われた

**`desktop` の SSH セッションに関わる 4 か所が書き足されました。**

- **「Preview your app」の注記**: SSH セッションでは Claude に Browser ペインのツールがないので、アプリをペインで開くことも、変更を自動で検証すること（auto-verify）もできず、ペインの **Dev servers** のメニューと設定したプレビューのサーバーも使えない、となりました。アプリを自分で見るには、リモートのマシンでサーバーを起動してから、そのポートを自分のコンピューターへ転送します。これまでの注記は、SSH セッションではツールがないので Claude はアプリを Browser ペインで開けない、自分で見るにはポートを転送する、だけでした
- **「Remote machine requirements for SSH sessions」の Network の項目**: 末尾の文が、Linux のリモートのマシンでその要求にプロキシが要るなら SSH セッション用に設定する、から、Linux のリモートのマシンにプロキシか CA 証明書が要るなら SSH セッション用に設定する、になりました
- **「Set a proxy or a CA certificate for SSH sessions」**: SSH セッションの Claude Code は `~/.profile` などの設定ファイルの変数を受け取らないため、セッションが止まったり、**The connection from … to the API failed** か **Authentication failed** が出たりする、という段落に、3 つ目のメッセージ **Claude Code on … couldn’t verify the API connection’s certificate** が加わりました。サインインし直しても直らない点は同じです
- **「Get Desktop's logs for an SSH problem」**: ヘルパーのフォルダー（`~/.claude/remote/run/` の下）からコピーするファイルが箇条書きになり、最新の実行のログ `remote-server.log` に加えて、あればその前の実行のログ `remote-server.log.old` もコピーする、となりました。`remote-server.log.old` は、Desktop が次に接続してヘルパーを起動し直すと失われるので、できるだけ早くコピーします。送る前に中身を確かめる点は同じです

changelog に対応する項目はありません。

## 3. setup の追加の依存関係に Git の版の条件が集められた

**`setup` の「System requirements」の「Additional dependencies」に、ripgrep に続いて Git の項目が加わりました。** Git は任意で、git が入っていれば `claude plugin eval` には 2.31 以降が要り、macOS・Linux・WSL からクラウドのセッションへローカルのリポジトリをアップロードするにも git 2.31 以降が要ります。版は `git --version` で確かめます。

どちらの条件も前から各ページに載っています。`claude plugin eval` の条件は `plugin-evals` の「Requirements」に（changelog では v2.1.283 で入ったもの）、アップロードの条件は `claude-code-on-the-web` の「Send local repositories without GitHub」にあり（ネイティブの Windows ではこの確認なしにアップロードする）、今回の項目はそれぞれへリンクしています。changelog に今回対応する項目はありません。

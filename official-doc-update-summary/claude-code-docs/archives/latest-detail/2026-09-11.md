## 1. クラウド 3 プロバイダーが first-party セッションと同じ扱いになった

過去 2 回のサマリを貫いていた「**同じ機能がプロバイダーによって違う挙動をする**」という記述が、今回まとめて畳まれました。

**きっかけは changelog の Changed 2 件**です。

- **Bedrock・Vertex・Foundry のシステムプロンプトが、環境・モデル・設定の詳細を「添付」として届けるようになった** ―― first-party セッションに揃えた、と書かれています
- **Bedrock・Vertex・Foundry のセッションが、会話を通じてツール一覧をバイト単位で安定に保つようになった** ―― 後から接続してくるツールはインライン定義を書き換えるのではなく deferred として読み込まれます。こちらも first-party に揃えた、と書かれています

**この 2 つが、リファレンス側の 3 つの書き換えに対応しています。**

**① システムプロンプトの「記録」が全プロバイダーで効くようになりました。** CLI リファレンスの `System prompt flags in resumed conversations` 節は、前回時点では「**記録が働くのはフィーチャーフラグを取得するセッションだけ**で、Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry では毎リクエスト組み立て直され `--system-prompt-snapshot` は効かない」と**現在形**で述べていました。今回その文は「**v2.1.268 より前は** …そうだった」という**版境界の記述に書き換わり**ました。Agent SDK のシステムプロンプト変更ページ（`snapshot` フィールド）も同じ形に揃い、環境変数リファレンスの「フィーチャーフラグの取得をオフにするとできなくなること」の一覧からは、**「再開した会話が記録済みのシステムプロンプトを保つ」という項目が丸ごと削除**されました。

**ただし「全プロバイダー」は「全セッション」ではありません。** **ベアモード（`--bare` / `CLAUDE_CODE_SIMPLE=1`）では、`--system-prompt-snapshot on` を明示しない限り記録はオフのまま**という記述はそのまま残っています。

**② 出力スタイルの切り替えが、無条件にキャッシュを保つ側へ移りました。** ここは 3 回続けて動いた箇所なので、経緯を整理します。

| 時点 | セッション途中の切り替えが適用されるか | キャッシュ |
|---|---|---|
| v2.1.251 より前 | されない | 保たれる |
| 2026年09月08日 の記述 | される | 全損 |
| 2026年09月09日 の記述 | される | フィーチャーフラグを取得するセッションでは保たれる／取得しないセッションでは全損 |
| 今回（2026年09月10日）の記述 | される | **条件なしで保たれる** |

前回時点では、`## Changing output style` の h3 は「**キャッシュを無効にするアクション**」の配下にあり、本文には**フラグを取得しないセッション（Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry）では従来どおり全損**という例外段落が付いていました。**今回、その h3 は「キャッシュを保持するアクション」の側へ物理的に移動し（一覧の箇条書きも一緒に移動）、例外段落は削除されました。** 残った本文は 3 文だけで、「`/config` または `outputStyle` 設定で切り替えると Claude は次のメッセージから新しいスタイルを使う」「**Claude Code は新しいスタイルの指示を会話中のメッセージとして届けるので、そのリクエストはシステムプロンプトも過去の会話もキャッシュから読む**」「v2.1.251 より前は、途中の切り替えはキャッシュを保つ代わりに `/clear` するまで適用されなかった」です。**「セッション最初のメッセージの前か `/clear`・`/compact` の直後に切り替えるとよい」という助言も、不要になったため消えています。**

**③ 「セッションの再開」が独立した h2 になりました。** これは前回の持ち越し 1 件です。**再開は、接頭辞のうち変わっていない部分を（キャッシュライフタイム内であれば）キャッシュから読みます**。システムプロンプトが変わる契機 ―― アップグレード、あるいは再開時に違う `--append-system-prompt` を渡すこと ―― があっても、**既定では再開した会話は開始時のシステムプロンプトを保つので、履歴は同じプロンプトの後ろに在り続け、変更はコンパクト後か新しい会話から効きます**。

この結果、**アップグレードの節にあった「再開は会話履歴全体をキャッシュヒットなしで再処理する。長いセッションに戻る最初のターンは最も高価なリクエストになりうる」という `<Note>` は、新しい h2 への参照 1 行に置き換わりました**。節本文も「**アップグレード後の最初のリクエスト**がキャッシュを最初から再構築する」から「**アップグレード後に始める最初の会話**が自分のキャッシュを最初から作る」へ変わっています。あわせて**レイヤー表のシステムプロンプト層の変更契機から「Claude Code がアップグレードされる」が外れ、「読み込まれたツール定義のセットが変わる」だけ**になりました。コンパクトの節には、**記録済みプロンプトを保ったまま再開した会話では、最初のコンパクトで現在のプロンプトに切り替わりその層が 1 回だけ再構築される**、という条件が加わっています。

**キャッシュスコープの書き方も、この方向と符合しています。** 「**システムプロンプトが**作業ディレクトリ・プラットフォーム・シェル・OS バージョン・自動メモリパスを**埋め込む**」という説明が、「**各会話が**作業ディレクトリ・プラットフォーム・シェル・OS バージョンを**持ち運び**、システムプロンプトは自動メモリパスを名指しする」へ書き換わりました。順次実行のセッションが接頭辞を共有する条件も、「システムプロンプトがブランチと最近のコミットを捕える」から「**各会話が起動時のスナップショットからブランチと最近のコミットを持ち運ぶ**」へ変わっています。

## 2. タスク追跡ツールの既定が拒否リストから許可リストへ反転した

**v2.1.268 で、タスク追跡ツールを既定で提供するかどうかの決め方が裏返りました。**

前回までの記述はこうでした ―― 「Claude Code v2.1.233 以降、**`TodoWrite`・`TaskCreate`・`TaskGet`・`TaskUpdate`・`TaskList` は Opus 4.8・Sonnet 5・Fable 5・Mythos 5 とそれらの系列の後継では、オプトインしない限り利用できない**」。**新しいモデルを名指しで除外する拒否リスト**です。

今回の記述はこうです ―― 「**タスク追跡ツールは、既定では Claude 3.x モデル・Opus 4 から 4.7・Sonnet 4 から 4.6・Haiku 4.5 でのみ利用できる**」。**古いモデルを名指しで許可する許可リスト**に変わりました。

**この反転で実質的に変わるのは、リストに載っていないモデルの扱いです。** 原文は続けて「**それ以外のすべてのモデルでは、オプトインしない限り Claude Code はツールを除外する。Claude Code が認識しないモデル ID ―― LLM ゲートウェイ越しに提供されるカスタムモデル名など ―― にも同じことが当てはまる**」と明記しました。拒否リスト方式では「名前が一致しないモデル」は既定でツールを持てたので、**ゲートウェイでカスタム名を配っている環境では既定の挙動が変わります**。

ツールが在るときの内訳は変わっていません ―― **4 つの Task ツールが提供され、`CLAUDE_CODE_ENABLE_TASKS=0` を設定した場合のみ代わりに `TodoWrite`** になります。オプトインの手段（`CLAUDE_CODE_ENABLE_TODO_TOOLS=1`、`--allowedTools`、`--tools`、Agent SDK の `allowedTools` / `tools`）もそのままです。環境変数リファレンスの `CLAUDE_CODE_ENABLE_TODO_TOOLS` の説明は、「**リストされたモデルで取得する**」から「**すべてのモデルで取得する**」へ書き換わりました。

**同じ書き換えが 6 か所に及んでいます** ―― ツールリファレンスの `Task tool availability` 節と冒頭のツール表 5 行、インタラクティブモードのタスクリスト節、環境変数リファレンス、TypeScript SDK リファレンスの `TodoWrite` と `TaskUpdate` の 2 か所、Python SDK リファレンス、Agent SDK の todo トラッキングページです。**いずれも「この既定セットは Claude Code v2.1.268 以降に適用される」という 1 文が添えられ**、SDK 側には「**TypeScript Agent SDK は v0.3.268 からこれを同梱する**」と書かれています。**反面、「TypeScript Agent SDK 0.3.233 以降ではこの制限が適用される」という旧来の版境界の文は削除されました。**

## 1. SEP 提出前のグループでの事前議論が必須に

SEP Guidelines の「Step-by-Step Process」で、事前議論の位置づけが変わりました。従来は `<Note>` の中で、採択の可能性を高めるための勧めとして「まず Discord の関連 Working Group / Interest Group でアイデアを議論する」ことが挙げられていました。今回その記述が本文に移り、冒頭に **Prior discussion is required.** と明記されています。SEP の作成者は、SEP のプルリクエストを開く前に関連グループの Discord で議論し、PR 説明にその議論（Discord のスレッド、WG/IG の会議メモ、GitHub Discussion のいずれか）へのリンクを載せなければなりません。リンクされた事前議論の無い SEP は受け付けられません。関連グループが存在しない場合は、GitHub Discussions か Discord の `#general` チャンネルで議論を始めることになっています。

これに伴い手順は 9 ステップから 10 ステップになりました。先頭に「**Discuss with the relevant group**」（該当グループでアイデアを練り、議論へのリンクを控えておく）が加わり、以降が 1 つずつ繰り下がっています。ほかに次の変更があります。

- 「Create a pull request」に、仕様リポジトリがプルリクエストを受け付けるのはコラボレーターからのみ、という一文が加わりました
- 「Formal review」に、スポンサーはステータスを `in-review` にする前に、グループでの議論が行われ PR 説明にリンクされていることを確認する、という条件が加わりました
- 「Finalization」の末尾に、マージされた SEP は SEP 索引に掲載され、`modelcontextprotocol.io/seps/<number>` の形で番号から直接開ける、という説明が加わりました
- `<Note>` に残ったのは、Core Maintainer の優先事項や設計原則との整合を確認するよう勧める項目だけです

同じ方針は Working and Interest Groups ページの FAQ「Do I need to be in a WG to submit a SEP?」にも反映されました。回答は「誰でも SEP を提出でき、グループへの所属は不要」のままですが、SEP のプルリクエストを開く前に関連グループの Discord チャンネルへ提案を持ち込む必要がある、という但し書きが加わり、SEP Guidelines の手順へのリンクが張られています。

- [SEP Guidelines - MCP Docs](https://modelcontextprotocol.io/community/sep-guidelines#step-by-step-process)
- [Working and Interest Groups - MCP Docs](https://modelcontextprotocol.io/community/working-interest-groups#do-i-need-to-be-in-a-wg-to-submit-a-sep)

## 2. Ruby SDK が Tier 1 に昇格

SDKs ページの「Available SDKs」の表で、Ruby SDK（`modelcontextprotocol/ruby-sdk`）のバッジが `Tier 2` から `Tier 1` に変わりました。表の並びも変わり、Ruby は Rust の直後、Java（Tier 2）の上に置かれています。

これで Tier 1 は TypeScript・Python・C#・Go・Rust・Ruby の 6 つ、Tier 2 は Java、Tier 3 は Swift・PHP・Kotlin となりました。変わったのは一覧表の区分だけで、各 Tier の要件を定めた SDK Tiers のページの内容は変わっていません（同ページの変更は表の書式のみです）。

- [SDKs - MCP Docs](https://modelcontextprotocol.io/docs/2026-07-28/sdk#available-sdks)

## 3. 拡張サポート表に mcpc MCP CLI が追加

Extension Support Matrix の「Support matrix」の表の末尾に、[mcpc MCP CLI](https://github.com/apify/mcpc) の行が追加されました。OAuth Client Credentials・Enterprise Auth・Skills の 3 列にチェックが付き、MCP Apps の列は空欄です。

既存のクライアントで、3 つの拡張すべてにチェックが付いているものはありません。Enterprise Auth のチェックは Archestra.AI に次いで 2 例目、OAuth Client Credentials と Skills（「Partial」ではない完全な対応）のチェックはいずれも初めてです。

- [Extension Support Matrix - MCP Docs](https://modelcontextprotocol.io/extensions/client-matrix#support-matrix)

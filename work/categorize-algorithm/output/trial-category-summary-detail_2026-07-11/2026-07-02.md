## カテゴリ別の変更点

### ⌨️ コマンド — 3件

- **daemon サブコマンドの誤解釈修正**: `claude --dangerously-skip-permissions daemon <subcommand>` がサブコマンドではなくチャットプロンプトとして扱われる不具合が修正された。あわせて `claude agents` のセッション行で、プルリクエストのリンクが冗長な「PR」ラベルなしの `#N` 表記になった。 — [English](https://code.claude.com/docs/en/changelog)
- **advisor 無効化時のフラグ挙動**: `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` を設定した場合の挙動が明確化され、`/advisor` コマンドは利用不可になり `advisorModel` の設定は無視される一方、`--advisor` フラグは受け付けられるが効果を持たないとされた。これにより同フラグを渡す既存スクリプトはエラーにならず動作を続ける。 — [advisor](https://code.claude.com/docs/en/advisor#turn-the-advisor-off) / [env-vars](https://code.claude.com/docs/en/env-vars#variables)
- **タスクリストと /tasks の区別**: `Ctrl+T` で切り替わるタスクリストが、Claude が多段作業の計画用に作る「To-Do チェックリスト」であり、実行中のシェルやサブエージェントを見る `/tasks` のバックグラウンドタスク表示とは別物であることが、キーボードショートカット表・タスクリスト節・キーバインド一覧のいずれでも明示された。表示は最大 5 件までで、チェックリスト項目が未作成の場合はトグルしても何も表示されない旨も追記された。 — [interactive-mode](https://code.claude.com/docs/en/interactive-mode#keyboard-shortcuts) / [interactive-mode](https://code.claude.com/docs/en/interactive-mode#task-list) / [keybindings](https://code.claude.com/docs/en/keybindings#available-actions)

### 🧰 拡張機能（プラグイン・スキル・フック） — 2件

- **スキル連鎖呼び出しと hook stderr**: `/skill-a /skill-b do XYZ` のようにスラッシュスキルを重ねて指定した場合、先頭から最大 5 個のスキルがすべて読み込まれるようになった（従来は最初の 1 個のみ）。また `SessionStart`・`Setup`・`SubagentStart` フックが終了コード 2 で終了した際に stderr が握り潰されていた問題が修正され、エラーがトランスクリプトに表示されるようになった。 — [English](https://code.claude.com/docs/en/changelog)
- **プラグイン作成手順の配置明確化**: プラグイン作成のクイックスタートで、プラグインディレクトリはテスト時に `--plugin-dir` で指定するため任意の場所（スクラッチフォルダ等）に作ってよいこと、および以降の手順は親ディレクトリから相対パスで実行することが明記された。既存設定をプラグイン化する手順でも、続く `cp` の相対パスが解決するようプロジェクトルートの `.claude/` と並べて作成する旨が追記された。 — [plugins](https://code.claude.com/docs/en/plugins#quickstart) / [plugins](https://code.claude.com/docs/en/plugins#convert-existing-configurations-to-plugins)

### 🔐 パーミッション・セキュリティ — 2件

- **plan mode のブラウザ操作確認**: plan mode が状態を変更するブラウザツール呼び出しに対して確認を求めていなかった不具合が修正され、読み取り専用の `browser_batch` 呼び出しは正しく自動許可されるようになった。 — [English](https://code.claude.com/docs/en/changelog)
- **dontAsk モードの状態表示**: `dontAsk` モードが有効な間、ステータスバーに `⏵⏵ don't ask on` と表示されることが明記された。 — [English](https://code.claude.com/docs/en/permission-modes#allow-only-pre-approved-tools-with-dontask-mode)

### 📚 セッション・コンテキスト — 4件

- 🆕新規ページ **Artifacts の Pro/Max 開放**: Artifacts が従来の Team・Enterprise に加えて Pro・Max プランでも利用できるようになった。Pro・Max では artifact は本人限定の非公開のままで管理者による管理も適用されず、組織メンバーへの共有は引き続き Team・Enterprise プランのみで行える。可用性表・機能可用性ページ・ツールリファレンスの記載もこの変更に追随した。 — [artifacts](https://code.claude.com/docs/en/artifacts) / [artifacts](https://code.claude.com/docs/en/artifacts#share-an-artifact) / [artifacts](https://code.claude.com/docs/en/artifacts#availability) ほか3箇所
- **バックグラウンドセッションの修正群**: バックグラウンドエージェントのデーモンが Linux で不正終了後に約 50 秒ごとに自死する問題、macOS の SSH 経由でのコールドスタート失敗、`claude stop` が再起動レースで無効化される問題、進捗インジケータの停滞、低メモリ機での不明瞭なエラー表示、agent view で Working と Idle が交互に点滅する問題などが修正された。また、新規メッセージのないセッションを開いたり再開したりするだけでトランスクリプトファイルが肥大化する問題と、`←` や `/background` でバックグラウンド化するとエージェント行の `/color` が失われる問題も修正された。 — [English](https://code.claude.com/docs/en/changelog)
- **SDK の自動メモリ書き込み要件**: Agent SDK の自動メモリについて、エージェントが専用のメモリツールではなく標準の `Write`・`Edit` ツールで新しいメモリを書き込むことが明記された。そのため、メモリを保存させるにはこれらのツールを有効にしておく必要がある。 — [English](https://code.claude.com/docs/en/agent-sdk/claude-code-features#control-filesystem-settings-with-settingsources)
- **チェックポイント例の実行前提**: チェックポイントのサンプルは「Refactor the authentication module」というプロンプトを使うため、認証モジュールを含むプロジェクトで実行するか、自分のプロジェクトに存在するファイル名にプロンプトを変更するよう追記された。また CLI から巻き戻す場合の `claude` 実行ファイルは Claude Code のインストールに含まれ、SDK パッケージでは導入されない旨が明記された。 — [English](https://code.claude.com/docs/en/agent-sdk/file-checkpointing#implement-checkpointing)

### 🤝 サブエージェント — 3件

- **agent view 手順の前提追記**: agent view のクイックスタートに、この手順には実行中のセッションが必要である旨が追記された。手元にセッションがない場合は別のターミナルで通常の `claude` セッションを開き、先にメッセージを送っておくよう案内される。 — [English](https://code.claude.com/docs/en/agent-view#quick-start)
- **バックグラウンドサービス起動表示**: `--bg` でセッションをバックグラウンド化したとき、バックグラウンドセッションをホストするサービスが未起動であれば、短縮 ID の出力に先立って `Starting background service…` が表示されることが明記された。 — [English](https://code.claude.com/docs/en/agent-view#dispatch-new-agents)
- **サブエージェントの既定バックグラウンド化**: サブエージェントが既定でバックグラウンド実行となり（従来は段階的ロールアウト）、実行中も Claude は作業を続け完了時に通知を受け取る。加えて、レート制限やサーバエラーで打ち切られたサブエージェントが部分成果を親に返すようになり、API エラー（利用上限到達など）を成功として報告する不具合も修正された。agent パネルでは稼働中の他エージェントがいるのに idle のサブエージェントが消える問題が直り、余剰の idle エージェントは展開可能なサマリ行にまとめられる。 — [English](https://code.claude.com/docs/en/changelog)

### 🔁 ワークフロー — 1件

- **ワークフロー例プロンプト追加**: ワークフローのページに「Example workflow prompts」セクションが新設され、多数ファイルの一括監査、チェックが通るまでの修正反復、隔離コピーでの並列マイグレーション、変更ファイルのレビューと単一サマリ作成といった典型パターンの依頼プロンプト例が示された。いずれもスクリプトを自分で書かず Claude にワークフローの作成と実行を任せる形である。 — [English](https://code.claude.com/docs/en/workflows#example-workflow-prompts)

### ⚙️ 設定・環境変数 — 2件

- **リトライ関連の環境変数と設定復旧**: `CLAUDE_CODE_RETRY_WATCHDOG` が非容量系の一時エラーに対する既定リトライ回数を 300 に引き上げ、`CLAUDE_CODE_MAX_RETRIES` の上限 15 の制限を撤廃するようになった。また、TLS 検査プロキシや `NODE_EXTRA_CA_CERTS` 未設定・証明書期限切れによる SSL 証明書エラーがリトライを消費せず即座に対処ヒント付きで失敗するようになり、起動時のリカバリダイアログから破損した設定ファイルをリセットする際は先にバックアップが取られるようになった。 — [English](https://code.claude.com/docs/en/changelog)
- **advisor 無効化時のフラグ挙動**: `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` を設定した場合の挙動が明確化され、`/advisor` コマンドは利用不可になり `advisorModel` の設定は無視される一方、`--advisor` フラグは受け付けられるが効果を持たないとされた。これにより同フラグを渡す既存スクリプトはエラーにならず動作を続ける。 — [advisor](https://code.claude.com/docs/en/advisor#turn-the-advisor-off) / [env-vars](https://code.claude.com/docs/en/env-vars#variables)
